# SPA／美容美體第一版模組

## 目標

把既有蒸管家的預約、顧客、方案與人員能力，整理成可重複套用的產業設定，而不是為每一家店複製一套頁面。

## 第一版已定義

- 顧客端用語：療程摘要、次、補做資格、我的療程、購買療程。
- 店長端用語：今日營運、預約管理、顧客管理、療程管理、芳療師管理。
- 角色：店長、芳療師。
- 預約資源：以芳療師個人可用時間為準；店長日排程使用 30 分鐘刻度，週一公休、10:00–21:00。
- 複合療程：一筆預約可選主療程＋多個加購項目，或直接選固定組合方案。
- 時間規則：服務分鐘數加總後，只提供同一位合格芳療師可連續完成的時段；服務後緩衝時間獨立保留。
- 第一版服務目錄：60／90 分鐘主療程、30 分鐘頭部／足部／臉部加購，以及 120 分鐘固定組合。
- 療程商品：新客體驗、單次芳療、3／5／10／12 次療程。
- 功能開關：方案、補做資格、分享店家開啟；健康評估關閉。
- 顧客端與店長端皆有不讀取資料庫的 Draft Preview。

## 安全邊界

- SPA Preview 只在非 Production 環境開啟。
- Preview 使用固定假資料，不讀取顧客、員工、預約或交易資料。
- 正式三家門市沒有指定產業模組時，持續使用既有蒸足用語與功能。
- 本階段沒有資料表 migration，也不會對 Production 執行 seed。

## 接上 Demo 資料庫時

1. 在獨立 `steamfoot-demo` 專案套用既有 Prisma migrations。
2. 執行 `npm run seed:demo:spa` 建立 SPA 假資料。
3. 將 Preview 環境的 `DATABASE_URL`／`DIRECT_URL` 指向 Demo 資料庫。
4. 驗證顧客端立即預約、預約詳情、我的療程，以及店長端預約與療程管理。
5. Demo 驗證完成前，不合併或套用到正式門市。

## 後續模組擴充方式

新增美容、美甲、髮廊或按摩模組時，建立另一份 `IndustryModule` 設定即可共用同一套畫面與流程。若產業有真正不同的規則，再以功能開關或小型策略函式擴充，避免在頁面內散落店名判斷。
