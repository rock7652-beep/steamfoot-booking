# P1 工具式 Agent 最小設計（未實作）

目標是接近Dot的自然助理體驗：**事實由工具提供，表達交給模型**。延續P0生成與費控，不回到單FAQ原文分類器。
本階段無tool-calling程式、無新表、無新通路或營運寫入，#1596封存不變。

| 工具 | 最小輸入 | 輸出／既有來源 | 安全邊界 |
| --- | --- | --- | --- |
| search_knowledge | query＋可選主題 | 已發布核准片段、sourceId/version/url | 伺服器注入品牌principal；模型不能指定別的租戶或內部文件 |
| get_plans | 可選已核准需求／方案id | PUBLIC_PRICING_PLANS＋當下有效優惠／最低承諾／加購條件 | 只讀同源事實，不接受模型指定價格或未核准優惠 |
| get_trial | 可選申請／起算／到期主題 | 共用試用政策＋申請入口／流程 | 只說明，不建立帳號、付款或承諾已聯繫 |
| get_public_cases | 可選產業、案例／示意類型 | PUBLIC_STORE_CASES及明確類型的公開展示 | 沒有同產業實店就回空集合＋限制；不查Store/會員或冒充案例 |

同一份Response schema、Provider與最終高風險驗證；工具是薄型唯讀adapter，不另建agent服務、向量庫或管理工作台。
工具輸出使用有界JSON：facts、sourceIds、version、urls、validAt及限制；知識內容仍作資料，不能成為指令。不得混品牌／門市資料表或共用未經授權的知識。
模型決定如何提問、組織答案與推薦，不負責編造工具事實。工具失敗回結構化錯誤，不把堆疊、憑證或整份DB資料交給模型。

## 呼叫與記憶

先保留P0最多兩次模型與單一12秒／token預算。需要工具後再生成也是新的付費模型呼叫，必須先占額度；不能把工具回合或修正當免費。若三個動作不能放入兩次限制，直接返回核准資料或要求釐清，下一階段另評估是否改預算，不能暗增。
固定LINE流程優先，原生reply token、白名單、去重、每日20、並行1及緊急停止沿用。只接品牌，不直接開其他五通路或門市操作。
短期記憶沿用固定30分鐘結構化profile、HMAC scope、世代／revision、成功發送後CAS及過期清除。多品牌接線前，scope須由伺服器principal＋channel identity導出，不由模型或客戶指定。
工具查詢的當下事實不能從記憶當權威；價格／額度／時效資訊每次重新核對。

## P2 長期記憶擴充方向（不在P1直接實作）

只保存明確同意的必要偏好／穩定需求，有來源與確認時間、可查閱更正刪除、明確保存期限及撤回同意流程。
顧客對話不自動變成知識；不永久存原文、聯絡憑證或跨店個資，不用過期偏好推斷當下營運權益。
優先在既有principal與資料生命周期上擴充，不先建立大型記憶服務。新schema及同意／刪除機制屆時獨立審查與授權。

順序保持：P0品質修復 → P1工具式Agent → P2長期記憶 → P3品牌任務及追蹤 → P4門市工具 → P5數位店長。
P1進入實作的前提：P0真實模型評估完成，錯誤分佈、來源召回及人工品質證據可追溯。
