# 大量資料與版面修正

範圍：先改善大量資料操作與本批截圖版面，再繼續新功能。沿用原 A 店預覽；正式站合併仍須完成驗收。

## 本批修改

- 顧客清單：資料庫篩選、排序、每頁 20 人與總數，同一查詢快照；只傳本頁及深連結顧客資料。保留 URL 篩選／頁碼與不捲動換頁；跨頁批次勾選保留，變更篩選才清除。電話不換行、姓名保留最小寬度，搜尋工具列在平板縮排。
- 持有方案：按需載入，每頁 20 張；有效與已到期／停用分開，支援方案／成員搜尋。依到期日排序，顯示可用、占用及到期，同名不同卡不合併。單張明細開啟後才讀額度紀錄。
- 共卡與顧客選擇：伺服器搜尋最多回傳 20 位，保留原已選成員；未選中實際顧客不能只輸入姓名送出。詳細卡片載入完成前不能儲存成員。
- 授課設定：每頁 10 項、搜尋及全部／已選篩選，完整草稿以 ID 保留；儲存驗證全部已選費用，錯誤項目即使在別頁也會顯示。費用仍一次原子儲存。工作連結及授課安排分頁籤；授課安排可按日期篩選與分頁，人員清單每頁 20 位。
- 指派結帳：方案／開發人超過 10 項時支援搜尋及鍵盤選取，小清單保留原生選單。
- 交易與上課：切換紀錄種類直接載入，每頁 10 筆，日期篩選使用台北營業日邊界；主要摘要直接顯示，付款／退款及操作備註放在各筆明細。
- 版面：取消按鈕不縮成直排，日期欄限制於容器內；首頁雙欄門檻調為 1024px；健康追蹤標示顧客姓名，工作端省去重複外框／標題及空值卡片，歷史趨勢獨立展開。

## 驗證與限制

- 本機完整 Vitest：5,295 通過、58 跳過、零錯誤；其後新增顧客跨頁選取回歸另行執行。TypeScript、修改檔案 ESLint 通過。
- UI 回歸覆蓋 100 課程跨頁草稿／隱藏錯誤、100 方案鍵盤搜尋、共卡原成員保留、卡片翻頁不累積、未選顧客不能送出、台北日期邊界。
- 首輪隔離資料庫測試抓到 PostgreSQL 將頁碼推導成 bigint，已將查詢輸出明確轉為 int，避免前端混用整數型別；須等待修正版四項測試全部通過。
- 新增四項真實 PostgreSQL 情境：1,000 顧客穩定分頁、全店搜尋、共卡可用額度與失效卡排除、店別／工作人員隔離；僅接受 loopback 且名稱以 `_test` 結尾的隔離資料庫，每次建立隨機 schema 並清除。由測試 PR 的既有隔離 CI 執行，不能將本機跳過視為通過。
- 2026-09-21 瀏覽器仍發生 `refresh tabs` 20 秒逾時。實頁、實體 iPad 橫直向／鍵盤／觸控尚未驗收，不能宣稱通過。
- 無新增資料庫遷移；未寫入 A 店測試人員／顧客或交易。
- 模板／方案設定仍載入設定清單，以保留完整資格／方案草稿；人員授課安排仍載入未結束課次摘要。此批將成長最快的顧客及持有卡片清單改為資料庫分頁，不宣称所有設定資料均已伺服器分頁。
- 健康歷史沿用最近 100 筆上限；單張卡額度歷史沿用最近 100 筆上限，沒有隱藏既有截斷條件。

## 預覽驗收

1. 顧客換頁／搜尋、批次選取跨頁、開詳情後返回；確認名稱／電話及頁碼。
2. 老師費用調整後換頁／搜尋／切已選，再回來確認草稿；一次儲存並重新開啟核對。
3. 多張同名卡依期限各自保留；共卡成員查找新顧客後，原成員仍在。
4. 指派方案／開發人搜尋與鍵盤操作，核對總額後以既有結帳流程驗收。
5. 交易／上課日期邊界與分頁，iPad 橫直向及手機鍵盤展開時能觸及主要操作。

驗收尚未全部通過，維持預覽，不合併正式站。
