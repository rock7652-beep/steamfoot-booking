# 教練授課時間與通知（2026-10-02）

## 使用方式

- 每週授課時間修改後可儲存；原已排課程保留，畫面列出超出新時段的課程。新增課程或修改日期、時間、教練時，運動教室也檢查可授課時間。只改備註、名稱等資料不重新檢查原時段。
- 單日請假仍需要先處理該日課程，與每週時段分開；不會因修改每週時間自動取消課程或扣退堂。
- 提醒管理 → 教練／老師：明日授課摘要、課程異動、體驗學員通知各自開關，預設關閉；開啟只記錄新事件。
- 明日摘要於台灣 21:00 建立，無課不發，只列本人授課，含體驗人數。課程異動與體驗資料由交易事件建立，成功操作後嘗試發送，cron 每分鐘補處理。
- 同一交易、同一教練、同一通知類型合併一張 Flex；超過八筆顯示其他筆數並連至本人課表。已送摘要後新增隔日課程會補充通知。
- 通知連結以 `view=work` 開啟本人工作課表及該日期；身分和名單仍由伺服器授權。

## 資料與交付

`CourseCoachNotification` 是交易內 outbox；課次及體驗預約觸發器只在該類型設定啟用後記錄。批次暫時取消／恢復只保留最早原始狀態與最後結果，沒有實際改變不發送。

發送前持久化重試 UUID、收件者及 Flex；重試沿用原內容，23 小時後停止自動重送。開關、店家提醒功能、有效人員與會員綁定、LINE 路由及共用提醒額度均需確認。未綁定、隔離預覽、無效事件及錯誤都保留紀錄。隔離預覽在任何 LINE 收件者探測與發送之前跳過。

資料表啟用 RLS，匿名／會員不得讀寫，僅伺服器可存取。遷移 `supabase/migrations/20261002093141_course_coach_notifications.sql` 已套用隔離測試資料庫，並於 2026-10-02 透過 `shared_fitness_ui_release_20261002` 套用正式資料庫（包含共用標籤、教師缺席返還、空間租借與權限強化）。教練提醒預設關閉；正式啟用前仍需驗收真實 LINE 送達，本次未向真實收件人測試，也未複製測試學員至正式資料庫。

Cron `/api/cron/course-coach-notifications` 需 CRON_SECRET，記錄 CronRunLog；每日 21:00–21:10 容許重啟補建同一摘要，唯一 ID 防重複。Vercel Cron 在正式部署運行，Preview 事件由操作後的 `after()` 處理，未自動執行每日 cron。

## 驗證

針對性 Vitest 驗證週時段保留、範圍提示、單日限制、21:00 時區邊界、空摘要、獨立開關、Preview 跳過、固定重試身分、綁定改變、額度和重試時限。隔離資料庫交易回滾測試確認同一課次連續異動只建立一筆通知並保留最初狀態；未留下課程／開關異動。另確認 RLS 開啟、anon/authenticated 無 SELECT 權限。實際外部 LINE 未測。

## 介面收尾

授課時段驗證會在原始行標示紅框與簡短原因（重疊、開始／結束順序、未填完整），不送出無效時段，修正即取消紅框。設定工作視窗共用固定寬高，讀取中與內頁切換不改變外框；內容捲動、未儲存保護保留。教練通知可在原視窗預覽，直接呼叫正式 Flex builder，使用示意資料，不觸發儲存或發送。教練、店長個別提醒及方案提醒統一左右開關；方案欄寬配合調整，避免開關擠壓輸入。
