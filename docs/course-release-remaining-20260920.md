## 固定發布與失敗處理順序

1. 確認實際恢復證據與限制、核准SHA／15份hash及維護窗口。合併可能觸發正式部署，不視為單純文件動作。
2. 正式schema／依賴／歷史再查核；任何partial狀態、hash差異或非預期pending停止，不盲跑整包migrate deploy。
3. 僅獲准後執行精確交易包，保留lock_timeout／statement_timeout。提交前失敗完整ROLLBACK。
4. DDL與歷史登錄完成才發布配對應用。歷史登錄失敗時保持入口關閉，核對後只補正歷史，不重跑DDL。
5. 正式冒煙範圍須獲准，檢查店別、角色、登入與必要交易，監看錯誤；其他店設定不變。
6. 提交後故障：停受影響的新寫入、回退相容應用並保留新結構／交易，前向修復；不DROP新表或用舊備份抹去期間營運紀錄。
