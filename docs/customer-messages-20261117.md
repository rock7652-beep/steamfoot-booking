# 自由編寫顧客訊息

需求來源：2026-11-17 使用者確認「選顧客 → 寫內容 → 選發送時間 → 預覽確認 → 發送」。
本次是獨立本地分支；未授權推送、正式合併、部署、正式 migration 或對顧客外發。原工作目錄未改。

## 功能

- 蒸足、音樂／運動、美業共用 /dashboard/customers/messages。入口整合於顧客管理右上角「發送訊息」與「發送紀錄」，側欄不重複設項目；顧客詳情另有「發送 LINE」。清單已勾選的顧客會帶入，後端重新核對當前門市、模組及權限。入口驗證見 customer-message-entry-20261117.md。
- 姓名、電話、LINE 名稱搜尋，依階段、LINE 狀態、既有可用標籤及負責人員篩選。完整範圍遠端查詢，每頁 25 位；跨頁選取、本頁及全部符合，最多 500 位。
- 文字最多 2,000 字，沿用系統既有 LINE Flex 轉換；無 AI、簡訊或 Messenger 擴充。
- 立即排入發送，或指定未來 90 天內台灣時間；預覽 15 分鐘有效，確認時固定收件名單。舊預覽僅是不可執行草稿。
- 預覽列可嘗試名單、排除名單與原因、時間、文字及 LINE 用量。依 LINE quota 實際回應判定，未配置管道、全域停發及隔離預覽皆不可送出。
- 發送紀錄最近 30 筆，顯示排程、接受、等待、失敗、略過與未知結果；取消僅停止未開始及後續重試，不能撤回正在處理的請求。

## 實作與邊界

- 新增 customer.message.send 權限，與 customer.read、可寫本店、LINE_REMINDER 功能共同檢查。OWNER 原有全權保留；MANAGER 新建預設加入，既有人員明確權限不自動修改。
- 草稿／確認／取消以本店與操作者核對。Worker 再核對原發送者的目前狀態、門市、權限、店家訂閱與功能。
- 收件人只用選定店家的已核對身分；禁止中央帳號備援。店家通道與收件人固定，合併、封鎖或身分異動則停止。
- 新增主資料庫兩個 outbox 表，20261117090000_customer_messages 為 additive migration，啟用 RLS 並撤回 PUBLIC／anon／authenticated 直接存取；由既有受信任伺服器資料庫連線操作。尚未對正式資料庫執行。
- 預覽時固定完整 LINE Flex payload，重試不隨後續格式變更而改寫。每位收件人使用固定 UUID retry key；五分鐘 lease、最多五次、初次嘗試起 23 小時內重試。超過窗口保留未知，不製造另一個 key 重送；舊 lease 的回應不能覆蓋新一輪結果。
- /api/cron/customer-messages 以 CRON_SECRET 驗證；每分鐘處理、每次最多 100 人且 210 秒預算，沿用發送前全域停發與預覽阻擋；本地修改 cron 設定不表示已發布排程。
- 預覽與驗收使用示範資料，未查詢或更改正式顧客，也沒有發送 LINE。Cloudflare 本次沒有路由或服務依賴變更，不是這次本機驗證的必要依賴。

## 驗證

- customer-message.test.ts：時間解析、無效日期、內容與收件人驗證、重試窗口。
- customer-message-outbox.test.ts：in-memory PGlite 執行實際 migration，覆蓋草稿不派送、確認重播、門市／操作者隔離、到期、額度、取消未知、lease 重用及 SQL 店家邊界；另用假 transport 測未知結果與確定拒絕。以 TZ=UTC 執行，對齊 Prisma timestamp 無時區的 UTC 讀寫；PGlite 預設 timestamp parser 隨主機時區解讀，不能混用。
- customer-message-access.test.ts：權限、可寫門市、功能及 cron secret；不呼叫真實 worker。
- Browser fixture 使用真正 composer 與獨立假 server actions，在 1366×900、1024×768、768×1024、390×844 驗排程、立即、排除、整批選取、確認回應遺失的同筆重試與取消；無整頁水平溢出，可見按鈕至少 44px。這是模擬尺寸，不是實機驗收。
- 元件截圖與結果：/tmp/steamfoot-customer-messages-qa，假資料，不能當成登入後完整業務或真實 LINE 送達證據。
- 最終 8 個測試檔案共 73 項通過（含 23 項本功能測試及指南、權限、導覽回歸）；TypeScript、修改檔案 ESLint、Prisma schema validate 及 git diff --check 通過。
- 程式已從原本顧客概況工作副本獨立出來，對齊本機 origin/main 182f70bcf；本分支不夾帶原顧客概況分支未合併的變更。

## 同日介面簡化

- 五步驟維持原順序；搜尋改為即時查找，顧客階段、LINE 狀態、標籤與人員收在「篩選條件」。收起後仍顯示已套用摘要，避免誤認搜尋範圍。
- 預覽優先顯示「傳給誰」「何時發送」「訊息內容」；用「預計發送」及「不會發送」說明名單。預估 LINE 用量持續可見，額度細節與補充說明按需展開。
- 確認按鈕標示發送人數；發送紀錄平時收起，建立訊息後自動展開。窄螢幕使用步驟進度文字，避免把五格導覽縮小。
- 簡化版截圖與結果另存 /tmp/steamfoot-customer-messages-simple-qa；1366×900、1024×768、768×1024、390×844 皆通過。新增驗證預設收合、套用後收合仍可辨識、慢速舊搜尋不覆蓋新結果，以及返回保留名單／文字／時間。
- 本輪只修改共用介面、既有指南與 browser fixture；無資料庫、發送管道、計費、權限或正式站變更。情境 02／03／05／08／10 以隔離元件實際操作驗證；不涉及課表切月、多人業務資料同步或 HQ 功能三態異動，正式登入／跨店整合驗收仍待隔離環境。

## 發布前仍須
