# 音樂與運動：指定學員、空間不限名額

承接 main b671bc61ea0a1991dc34703e63648f2dc0d4c76c，依 docs/course-decisions.md D009 及本對話 2026-11-11 最新確認。與其他未合併的方案權益 PR #1538 不混合。

## 根因與範圍

正式銀百合指定課的 CourseSession.capacity=1、enrollmentMode=OPEN，但 SportsStagingSessionRule.enrollment=ASSIGNED。舊前後端直接比較有效人數與 capacity，造成第一人後加人就誤認超額。唯讀同時查得空間的舊容量值仍存在；本次不批次改正式資料。

共用純函式優先採運動專屬持久化模式，其次採音樂課次模式／指定對象。指定學員不檢查課次名額；開放選課、含固定名單的混合課及未知模式保留名額檢查。前後端一般學員、體驗客、系列加人、固定系列展課、請假恢復、補課與排課修改依同一規則。客戶仍不能自行報名指定課。重複、學員撞期、方案適用／效期、扣抵、月預約方案限額、門市權限、教師與空間時段占用不放寬。

音樂及運動空間不再設容納人數：既有 capacity 數字不再用於排課、教師時段搜尋或加人；新建與使用者儲存時寫 null，沿用原版本比對及收據。移除原生空間清單／編輯容量欄位；美業共用來源不套用這項業務變更。指定學員排課不再顯示名額輸入，課表與首頁摘要只顯示人數，不顯示假滿班。

## 驗證證據與限制

- 本機瀏覽器使用實際 CourseRoster、完整樣式，網路／伺服器 actions 全數攔截為合成資料。運動／音樂 × ASSIGNED／OPEN × 1366×900、768×1024、390×844 共 12 案。舊 capacity=1 且已有一人：指定模式送出一般學員時零確認、送出 allowOverCapacity=false；OPEN 一次滿班確認、按取消零新增操作。全部無頁面溢出或瀏覽器錯誤。代表截圖與 results.json 在 artifacts/course-assigned-unlimited-20261111。
- 本機課程／運動廣泛回歸首輪 400 檔：384 通過、14 跳過，3 個舊容量期待已依本次決策調整。開發期間全庫 1,787 檔：1,752 通過、33 跳過，兩項失敗是過渡版本／舊容量預期；調整後重驗對應案例。最終整份結果以最終 PR head 的 CI checks 及發布收據為準，不把開發中全庫結果記為完整通過。
- 混合排課隔離 PostgreSQL 的舊指定課最後一席測試，改為 ASSIGNED／OPEN 各一案：同時替兩位學員安排，指定模式兩筆成功且各保留個人方案額度，OPEN 僅一筆成功。CI 保持不得跳過的完整檢查，案例數由 39 更新為 40。
- 完整 TypeScript 與修改檔 ESLint 檢查；既有兩個 unused-vars warning 不屬本次業務邏輯，無新增錯誤。
- 正式僅唯讀查核設定及觸發器，未新增預約、點名、扣堂、收款、變更空間或發送通知。無 schema migration。
- 這些是合成流程驗證，不是正式登入後的真實加人驗收，也不宣稱既有補登時間／所有方案資格問題因此修復。

候選分支停用自身重複的自動 Preview，正式 main、建置守門與通知停發設定不變。尚未發布時不得稱正式已修復。
