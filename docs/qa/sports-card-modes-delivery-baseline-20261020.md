# 運動兩種選課模式：修改與交付驗收基準

狀態：需求基準固定；權益、購買快照、排課與固定課點名自動選卡、必要表單及會員資格顯示已在獨立分支實作。本機隔離交易與元件驗證見 `sports-card-modes-implementation-20261020.md`；隔離 Preview 登入與尺寸驗收尚未完成。程式盤點基準為 main `8d717d5dc45da6fbd4e2984afea48165140281b3`。本文件不是正式版已支援的宣告。

## 固定需求與範圍

保留「教學項目／收費方式／教練管理」三個入口，沿用既有清單與右側編輯面板，不增加精靈、模組或重做導覽。以下「開放選課」沿用既有模式名稱；通用卡只適用開放選課。

| 設定／操作 | 指定學員 | 開放選課 |
| --- | --- | --- |
| 教學項目 | 定義教什麼、合資格教練 | 定義教什麼、合資格教練及本課扣抵規則 |
| 收費方式 | 指定項目方案：綁定一個教學項目，設定售價、額度、期限與扣抵規則 | 開放選課通用卡：設定售價、額度與期限，不綁單一項目 |
| 教練管理 | 按教學項目維護資格，同項目的不同售價方案共用資格 | 按教學項目維護資格 |
| 排課必填 | 教學項目、教練、時間、學員 | 教學項目、教練、時間、名額 |
| 排課收費方案選單 | 移除必選 | 移除必選 |
| 核對權益 | 學員持有的該項目有效方案 | 學員持有的有效通用卡 |
| 扣抵來源 | 實際使用的學員方案規則 | 本堂開放課程規則 |

兩種模式可共用同一教學項目，但權益不可混用。購買額度只是數量，不能自行將「點／堂／格」互換。保留既有支援單位及其限制，不承諾新增換算功能。

| 編號 | 修改與完成條件 | 主要現有位置 |

| M3 | 教學項目既有編輯面板補開放選課扣抵設定，供排課產生本堂規則快照；修改設定只影響後續建立課程。不得改寫已排課與已扣抵歷史。 | `music-subject-catalog.tsx`、教學項目儲存服務、課程模板與快照 |

| M7 | 保留交易鎖、容量、重送去重、到期與可用額度核對。有限批次課沿用整批足額檢查，不偷偷拆卡；永久固定名單沿用點名時才選卡扣抵。取消、還點、更正依原預約快照，教練計酬依原已保存規則，不重算歷史。 | 排課分配、預約、扣還點、永久系列及計酬服務 |

以上檔名是影響範圍，非限定只能修改這些檔案。只允許為完成這些行為修改必要相依處；不新增方案專屬教練限制、任意換算、促銷或其他介面功能。

## 最小交付驗收

所有新增交易驗收使用隔離環境及合成學員。表內案例目前均待執行；既有測試只能證明原守衛，不可替代新增模式驗收。

| 編號 | 情境 | 必須觀察到的結果 |
| --- | --- | --- |
| A1 | 同一項目建兩個不同售價／額度／扣抵方案 | 共用項目教練資格；排課不選方案；兩位學員各按自己購入方案正確扣抵 |
| A2 | 學員只有其他項目方案或只有通用卡，加入指定課 | 拒絕使用不相符權益；不產生扣抵或占位副作用 |
| A3 | 同一學員有多張同項目有效卡 | 自動使用足額且較早到期的卡；不足額／過期／停用卡不誤用；結果可追查至實際課卡 |
| A4 | 只購買一張通用卡，報名兩個不同項目的開放課 | 不要求另買項目方案；分別按各堂規則扣抵，餘額正確 |
| A5 | 只有指定項目方案，報名同項目開放課 | 不誤當通用卡；前台資格顯示與後端拒絕一致 |
| A6 | 同項目同時排指定課與開放課 | 分別使用所屬權益；無方案 ID 的正式開放課不被建立為體驗 |
| A7 | 更改方案規則／開放課扣抵後再排課 | 新課使用適用的新規則；既有預約、扣抵與計酬快照不變；已售權益不被悄悄重新解釋 |
| A8 | 有限批次與永久固定課 | 前者整批足額才成功；後者維持原名單占位與點名扣抵時點；不新增排課當下扣款 |
| A9 | 重送、最後一個名額競爭、額度不足 | 不重複扣抵或超收名額；失敗交易整筆回退；候補遞補仍核對正確權益 |
| A10 | 取消／改課／點名更正／補課 | 按原課卡及扣抵快照還點，不重複還點；改課與補課不繞過模式及項目限制 |
| A11 | 跨店、無權限、非合資格教練、撞課 | 原後端拒絕守衛仍生效；不能只靠 UI 隱藏 |
| A12 | 舊方案、舊卡、舊預約及音樂模組 | 維持原邏輯；沒有自動資料轉換；共用表單與服務不改變其他模組行為 |
| U1 | 後台桌機與 iPad：三入口新增／編輯、排課與返回 | 欄位依類型正確顯示；不再必選購買方案；儲存／取消與錯誤保留輸入；觸控及窄容器符合 Framework |
| U2 | 會員報名入口手機 | 只顯示可用權益，扣抵預告與後端一致；拒絕情境可理解；不新增前台操作指南 |

## 實作與交付順序

1. 先完成 M1 與共用資格／扣抵判斷，再接排課與購買快照；後續 UI 依同一判斷呈現。
2. 完成 M2–M5 必要欄位，沿用既有元件，不擴大介面設計。
3. 先跑 A1–A6 核心交易，再補 A7–A12 回歸；通過型別與相關靜態檢查。
4. 在隔離 Preview 完成 U1、U2 及登入後核心交易，記錄版本、尺寸、案例、結果與限制。既有操作證據只引用未變動行為，不重跑整套。
