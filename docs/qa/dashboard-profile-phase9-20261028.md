## 第一版實測與新的發現

兩個 Preview 均部署 `d30f12a528ca14e3f2c04545e9459133db4bd002`。音樂完整開頁至六筆方案可見 7,852／4,327／4,130 ms，運動 3,659／4,586／4,519 ms，美業 5,464／3,906／4,007 ms；桌機及兩種 iPad 尺寸無整頁水平溢出。此樣本不足以證明外框並行使整體開頁達標，也不能忽略音樂 7,852 ms 的慢樣本。

音樂第一輪期別與購買資料同時請求，期別 GET 1,254 ms，購買 GET 3,683 ms；畫面原先等待兩者，因此確認期別會被較慢的收款紀錄阻擋。第二版變更使經授權的期別回來後先顯示，收款紀錄尚未回來時明示「收款紀錄讀取中」，不顯示未確認的金額；切學員、權限或修訂時的前次資料及晚到回應不得套用。相關介面測試涵蓋分段成功、讀取失敗、學員切換與晚回應；第二版仍待同版本 Preview 實測。

運動名單就緒後連續開合 12 次，有 3 次發生瀏覽器文件重新請求，分別等待 20,466／11,263／11,699 ms。獨立的瀏覽器追蹤再次捕捉到 11,358 ms，Chrome 呼叫堆疊指向 Next.js App Router `mpaNavigation` 的 `location.replace`；前一次關閉視窗寫入網址後約 209 ms 出現硬導航。這證實實測中存在框架整頁導航及重讀，尚未證明網址同步必然是觸發原因，也不能斷定昨天實際店長的事件相同。不能以未重現的快速樣本宣稱此問題已修好；接下來應繼續釐清導航觸發條件並測試慢網路與切換。

第一版完整回歸 1,468 檔／14,210 項通過、22 檔／191 項跳過。第二版首次完整回歸 14,213 項斷言通過、191 項跳過，但 Vitest 回報一次 beauty-display-order 工作程序關閉期間未處理錯誤，單檔 6 項重跑通過；整套重跑中，不把第一次寫成全綠。


## 第二版實測與測試收尾

兩個 Preview 同版來源 `d87cd327839c85c2d0596824d086b2e92b9ce5e6`。真實登入並以既有隔離資料唯讀測試，完整開頁至方案可見：音樂六筆 3,366／3,971／3,363 ms；運動一筆 3,166／4,001／3,772 ms；美業一筆 5,112／4,233／3,716 ms。三種尺寸皆無整頁水平溢出。這些小樣本僅供比較，不等於正式站效能或即時保證。

音樂另一項受控測試刻意將購買紀錄回應延遲 4 秒：方案在點開後 1,413 ms 已先顯示，讀取中提示可見且未顯示未確認的收款金額；收款資料於 7,766 ms 顯示。人工延遲不能拿來代表正常讀取時間。

第二版完整回歸重跑結果為 1,468 檔／14,213 項通過、22 檔／191 項跳過；第一次測試工具關閉錯誤及單檔重跑結果保留於上方。三個新測試帳號與店員已停用並驗證，兩個暫用 Preview 分享已撤銷；本輪未新增購買交易。

待辦：追查運動偶發整頁導航的具體觸發條件、釐清外框及授權等待與網路時間，並在可重現的真實測試環境持續量測；現有數據不能證明問題已完全修復。尚未更新正式站。
