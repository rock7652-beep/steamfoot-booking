# 運動模組公開體驗預約表單

## 需求與入口

沿用舒生活「圖文選單 → 本店 LIFF → 公開體驗表單」流程，新增運動模組入口 `/sports-trial/[slug]`。銀百合使用 `silverlily`。既有 `resolveBookingLineEntry` 產生圖文選單網址，不手填猜測 LIFF ID，不變更既有部署通道設定。

已設定且啟用 `business.fitness`、未啟用 `business.music` 的 COURSE 店家，其 `/liff/public-trial` 轉至運動表單；音樂保留原會員流程，美業／蒸足保留既有表單。未設定 LINE 不借中央／其他店帳號，未驗證入口不可送出。

## 使用流程與規則

1. 本店 LIFF 驗證 Login audience，並核對 Messaging API 身分相容性，取得短效不透明預約憑證。
2. 選擇公開體驗課與時段，顯示價格及剩餘名額。
3. 填寫本人姓名、手機及同意資料使用，每次一人。首次身分沿用既有課程 LINE 登記服務；既有會員不覆寫姓名手機，不以電話接管既有資料，衝突由門市核對。
4. 預約沿用 `reserveCourseInTransaction` 的運動體驗規則、門市鎖、名額／重複／重疊檢查、截止時間、開放期限與公休日限制。預約不扣卡、不收款、不標為出席。
5. 憑證消耗與預約在同一交易提交。相同請求與原始資料重試回傳原結果，不建立第二筆。斷線時保留並鎖定原資料供重試。

公開列表只含啟用且公開的未來體驗課，原生規則須為 OPEN、未綁付費方案、有名額且未取消／釋出／教師請假。保留店家開放選課、體驗與預約期限設定；不為銀百合自動打開開關，不把指定學員課公開。保留既有收費快照，提交再核對當下價格與門市、模組及身分資格。

首次登記與預約是兩個既有服務交易：若登記後名額被搶走或預約失敗，已驗證的新會員資料會保留，沒有成功預約或收款。表單預先說明首次預約建立本店顧客資料。

## 驗證

- 新增服務／門市測試及既有 LINE 入口、登記、課程期限、自助預約回歸測試，最終結果見本次執行紀錄。
- TypeScript、修改檔 ESLint 與 diff 檢查。
- `scripts/qa/sports-public-trial-browser.mjs` 使用實際 React 表單、合成課程與合成送出，攔截全部外部網路，不讀正式資料或呼叫 LINE。
- 360、390、768、1024、1366 寬度無橫向溢出；輸入字體至少 16px、主要按鈕至少 44px；返回／縮放保留課程與聯絡資料。
- 驗證兩步流程、無課狀態、未驗證禁止送出、斷線後相同 payload 重試及合成成功頁。
- 證據：`evidence/20261027-sports-public-trial/`。僅為隔離預覽，非正式預約或 LINE 真機驗收。

## 發布與待辦

尚未正式發布、建立正式測試預約、外發訊息或修改 LINE 圖文選單；沒有資料庫遷移。依 AGENTS.md，正式站合併需要使用者明確授權。

發布前核對銀百合現行開放選課／體驗開關與至少一堂可公開體驗課；本次未讀取正式設定，不以歷史紀錄當成現況。若仍關閉開放選課，表單顯示沒有開放體驗課，須另確認店家期望的開放範圍。

發布後從官方帳號真機點入、逐人建立一筆經授權預約，確認後台課程、名額、金額及門市身分；通知送達須另行實測，不因成功頁就宣稱已發送。圖文選單填入經既有設定產生並驗證的本店公開體驗 LIFF 連結。
