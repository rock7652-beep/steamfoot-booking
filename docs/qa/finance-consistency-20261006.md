# 金流一致性修正與驗收 — 2026-10-06

## 定案與範圍

目標：操作簡單、金額正確；店員維持開單、收款、結帳。防重送、現金判斷、對帳在後端處理。

本支線修正現有銷貨／課程方案／體驗收款、收支帳及現金抽屜。工單另行接入，不在這次新增工單介面、HQ 開關或列印功能。保留既有模組業務規則、付款授權與庫存流程。

## 已修正

| 問題 | 結果 |
|---|---|
| 課程營收組成同時計算 CoursePurchase／TrialPayment 和自動入帳 | 課程改以 CashbookEntry 的記帳日、金額為唯一財務來源；方案、混合體驗收款、退款與沖銷只計一次 |
| 授課費／利潤誤登沖回算成新收入 | 沖回降低對應支出，不增加營收 |
| 銷貨／手動收支／課程體驗／租借異動與閉店計算並行 | 金融異動在同一交易鎖定抽屜列並提高 updatedAt 版本；閉店 CAS 防止舊計算寫入 |
| 蒸足方案、單次、體驗、退款建立交易 | 共用 createFinancialTransaction；判斷實際現金拆分，明確固定交易日期；待付款、非現金及扣堂不影響抽屜 |
| 閉店遭遇收支異動 | 最多自動重新讀取計算 3 次；持續衝突明確回傳尚未結帳 |
| 付款方式更正／作廢 | 現金來源套用同日鎖定；混合付款不可只修改整筆付款方式；原本更正／作廢稽核保留 |
| 手動新增記帳網路重送 | 兩個既有視窗自動帶同一 requestId；店別／操作者／請求 ID 對應唯一 entry ID；內容相同重送回原結果，內容不同拒絕 |
| 手動記帳日期依執行環境偏移 | 共用 UTC 午夜日期解析並驗證真實日期 |
| 手動收支修改／刪除 | 更新以原 updatedAt 版本比對；已閉店現金不可直接刪除；已授權補紀錄保留閉店快照與稽核 |
| 蒸足營收組成的日期／付款狀態 | 使用 transactionDate，納入 SUCCESS／CONFIRMED，排除 voidedAt |
| 對帳僅比較同一來源不同加總 | 新增銷貨／進貨實收、分配、入帳、單據已付比較；本月已結帳現金快照與目前来源比對；差異保留單號與金額 |
| HQ 關閉進銷存後的歷史金流 | 對帳仍讀歷史來源，不以功能開關排除既有帳；完整結果沿用進貨成本權限保護 |

## 驗收限制與發布門檻

- PGlite 是單一記憶體資料庫；SQL 與舊版本失效已驗，尚不能當作 Supabase 多連線並行實測。
- 尚未逐筆核對正式店家歷史帳務；没有重寫金額、修改歷史資料或執行正式對帳寫入。
- 既有「已結帳補紀錄」是歷史補登，不代表當日實體現金已調整；新對帳會揭露差異，不自動改寫凍結快照。
- 課程資料若來源已確認但缺入帳，新報表不從來源補算，以免掩蓋問題；既有課程對帳應回報缺漏，需先核對。
- 本輪統一的是營收組成的實收口徑。其他按成交日／建立日顯示的業績報表不能直接與抽屜現金餘額比較；未宣稱所有歷史報表定義均已改寫。
- 手動新增舊呼叫者若未傳 requestId，仍維持相容；兩個日常記帳入口已帶入。此 ID 防網路重送，不判定店員另開新單是否重複輸入。
- 進銷存既有版本未提供完整退貨／退款流程，本次不新增；退款不自動回補庫存。
- Preview 尚須完成桌機、iPad 既有記帳視窗與隔離店完整業務操作，包含兩位操作人員同時收款／結帳。
- CI 與 Preview 業務验收通過後，再由使用者明確授權合併正式站。
