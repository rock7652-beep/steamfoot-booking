# 四模組購買交易取消發布前驗證

決策來源：本次對話同意「具權限者關帳後仍可取消購買交易，原因選填；補登依需要選擇，保留使用／預約／退款檢查」。入口與規則核對見 `docs/transaction-v1-acceptance-checklist.md` 本次決策段。

## 實作範圍

- 延續蒸足取消原因選填的本地修改。
- 運動／音樂與美業的購買取消，允許在原收款日期已關帳時沖銷。僅取消路徑傳入 `allowClosedSupplement`，一般收款、退款及其他付款仍沿用原規則。
- 沖銷沿用原收支日期，保留原付款與已實點的現金快照；不建立今日現金退款、不自動執行外部退錢。
- 音樂獨立繳費交易不再因有付款明細而被迫使用退款；核對各收款與連動現金帳、實收合計後，逐筆以原日期沖銷。保留所有原收款紀錄。營運及顧客交易兩個入口均保留權限並提供作廢。
- 共用作廢表單不要求原因，作廢可單獨完成，不強制補登。未填時原交易／美業修訂的原因為 null，仍保留操作人與異動時間；有填時保留。
- 未放寬方案已使用／已預約、複數來源、既有退款、門市與角色權限、交易重送等檢查。一般資料更正、退款原因仍依各自規則。

## 證據與限制

- 113 項相關本地回歸測試通過：三模組後端取消、原因省略／空白、有原因、權限與資料隔離、關帳後作廢、音樂多筆繳費沖銷及來源不一致拒絕、既有報表與顧客交易入口。
- 實際元件合成瀏覽器：`node scripts/qa/module-purchase-cancel-browser.mjs`，產物 `/tmp/module-purchase-cancel-preview`。運動、音樂（含獨立付款資料）、美業各驗 1366×900、1024×768、768×1024、390×844，共 12 個案例。空白可送出、僅送一次、無強制補登，原一般更正原因檢查保留，無頁面橫向溢出。
- 蒸足既有合成預覽另驗 5 種尺寸的選填原因與取消後補登。
- 瀏覽器為模擬尺寸、合成 server actions，封鎖網路；不是實機／登入後正式帳務驗收。所有測試未修改正式交易資料。
- 本次未調整體驗收款、授課費付款、租借、進銷存與手動記帳，也未統一其他模組的補登表單。不得據此宣稱所有種類交易均可直接刪除或任意修改收費。
- 先前的 GitHub 推送及建 PR 曾因缺少指定倉庫傳送授權而被自動審核擋下，未執行。使用者現已明確同意將本次四模組修改上傳至 rock7652-beep/steamfoot-booking、建立 PR 並部署正式站。本紀錄為發布前證據，正式可用以實際 CI 與部署結果為準。
