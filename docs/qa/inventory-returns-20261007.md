# 銷貨退貨、退款與收款更正

基準主線：95dd0b8。支線：feat/inventory-returns-20261007。依 Framework v1.5，共用 ModalPanel、原清單與 dirty guard；HQ 仍使用既有 read/write store 邊界。

## 已實作
- 銷貨單：全部／部分退貨、按實際折扣成交價退貨、贈品零金額、逐項選擇可售回庫、運費獨立退還、整單作廢、延後或分次退款、待退款篩選。
- 收款紀錄：整筆作廢或更正付款方式，批次關聯全部銷貨單；保留原收款及沖回紀錄、替代收款關聯。這是記帳更正，不是實際退款。已退貨、含工單的收款更正先阻擋。
- 換貨：新開銷貨單，再於退貨關聯同顧客的新單，兩邊可互相查看；各單分別結清，沒有跨單自動抵扣。
- 資料：原單第一次退貨前的商品快照、各次處理原因／人員／日期／退款／回庫選擇保留；日期不能早於原單、最近收款或前次退貨，不能晚於今天。
- 帳務：退款以實際日期登錄；收款更正沖回原方式，再建立替代收款。銷貨報表分列銷售、退貨及淨銷售；營收分析的退款及收款更正不計入一般營運支出。已結帳日現金交易維持原 lockCashDay 阻擋。
- 權限：inventory.refund 與 inventory.payment.correct 分開；新建店長預設含、普通人員不含，既有人員授權需按既有機制配置；成本仍不對無權限人員暴露。
- 來源：手動零售提示不扣庫存、避免重複記帳；現金帳連動項目可連回原單，禁止直接改刪。

## 驗證證據
- 7 個測試檔共 97 項通過：折扣分次尾差、未收款／部分收款、延後退款、贈品、運費、損壞不回庫、過量／重複／跨店／舊版本／權限拒絕、請求重送、收款作廢／方式更正、營收報表、既有進銷存與列印回歸。
- TypeScript noEmit：通過（先生成三套 Prisma client）；修改的交易服務與表單 ESLint：通過；git diff --check：通過。
- Server service 測試使用記憶體交易介面；不是 PostgreSQL 真實交易回滾或並發測試。
