# 購買狀態核對與取消：整合候選（2026-10-28）

## 範圍與狀態

這是預設關閉的候選，不是正式上線或已完整驗收。課程及美業多次方案使用按門市／顧客的持久購買意圖；美業單次與體驗收款使用預約集合的意圖及每個預約的未結限制，包含訪客。三者均在原交易使用的門市鎖下提交、取消和確認；取消未到達的請求也會留下墓碑。已完成但尚未確認仍阻擋下一筆，操作人員明確確認後才解除。已部署或飛行中的舊版本不受新契約自動保護，不可在舊請求未排空時啟用。

新意圖僅存伺服器端 HMAC，不存付款表單原文；瀏覽器只存非付款 scope 與隨機 requestKey。網路、狀態查詢或送出超過八秒會維持不確定，不自動重送；重整後查不到不代表原請求失敗。同一分頁可找回 key，另一裝置可找回已抵達伺服器的未確認狀態；另一裝置無法觀察一筆尚未抵達伺服器的請求，不能承諾絕對跨裝置防重。密鑰輪替後未結請求須重新核對或安全取消。

本機編輯包含三個 migration，但未套用遠端：`prisma/migrations/20261028111122_course_purchase_intent`、`supabase/migrations/20261028111327_beauty_plan_purchase_intents.sql`、`supabase/migrations/20261028112155_beauty_collection_intents.sql`。課程、方案及單次收款各自 flag 預設關閉；正式部署和資料庫變更需另行完成完整驗收與上線安排。

## 驗證

本機隔離 PostgreSQL 16 執行實際 migration 與交易競爭：同 key 重送、同顧客不同 key、已提交待確認、提交先鎖／取消先鎖、取消後晚到、回滾、RLS、唯一索引及美業重疊預約集合。部分課程實際 checkout service 測試使用 Prisma adapter、通知與計酬替身，不能作完整正式帳簿驗收。相關 16 檔 172 項通過，完整 TypeScript 通過。ESLint 無錯誤，課表原有 ref cleanup 一項警告。

隔離本機真實登入運動後台，桌機 1366×900 與 iPad 1024×768／768×1024 的購買表單未見整頁溢出。正常購買、伺服器處理後丟失回應、重整顯示未確認及取消後晚到拒絕均有實測；針對回應遺失那筆後續 UI 明確確認，資料庫已寫入確認時間。兩筆測試交易各一筆、10 點／NT$1,000，各一張卡；本機收入合計 NT$2,000。存在一筆首次狀態讀取逾時及一筆缺少店長的失敗樣本，均保留；逾時原因尚未確定。測試期間開發工作區曾熱重載，樣本不能當成同一精確快照。詳細證據見 `artifacts/purchase-intent-local/README.md`。
