# 課程成本核對、快照與既有測試清理

正式站的實際購買／排課／收款／退款驗收由店家稍後進行。本批只做唯讀歷史盤點、程式與合成資料驗證，沒有對正式資料回填成本或建立帳務。

## 歷史盤點

盤點涵蓋已開通音樂／運動的店家；候選CSV及核對說明放在工作區 outputs/course-cost-review-20261026，商業收費明細不提交Git。

0成本只代表待店家確認，不能推定資料錯誤。原輸入未保存，不能從現價、教師費或店家分配金額反推成本；不回填歷史卡片、交易與已結算資料。

## 成本核對頁

入口：收費方式右上「成本核對」，路徑 /dashboard/courses/cost-review。店長／管理者需 report.read、transaction.read、wallet.read 與 BASIC_REPORTS。標記核對另需 plans.edit、可寫店家及有效訂閱；HQ唯讀模式不提供確認按鈕。授課費另需 cashbook.read、teacher.compensation.read、teacher.settlement.read 及整店教師財務範圍。

- 目前收費：列一般與體驗成本。核對只新增版本化稽核紀錄，不修改費用或帳務；缺少適用的體驗成本／格式不正確不能確認。
- 核對版本包含價格、成本、數量、單位、期數／贈送堂數與體驗條件。若已變更，拒絕舊版本的確認。重送使用同一稽核identity，不重複建立紀錄。
- 後續店長購買與顧客購買，建立訂單時在同一交易保存成本quote，後來更改價目不改舊quote。0成本需有對應版本的店長確認，才列入已知差額。
- 一般交易依確認月份查詢，顯示目前累計實收／退款；缺少quote、購買期數／基準不同、退款、未收足或作廢不推算差額。
- 體驗依收款或作廢月份查詢，先使用該收款稽核成本，否則僅使用課次的不可變quote。明確unknown保持unknown，不讀今天價目；免費體驗可顯示負差額。作廢／更正不列入已知差額。
- 授課費沿用原月結計酬讀取，依上課月份另列；不與收款日期差額直接相減，也不改月結分潤。
- 合計只統計已知子集，不是完整淨利或現金流；全部unknown時顯示待核對而不是0。大於本頁上限的資料明示停止，不顯示截斷後的金額合計。

使用既有AuditLog JSON，不需要migration。一般成本與店家收入分配快照分開，避免把 storeCostSnapshot 誤作費用。
