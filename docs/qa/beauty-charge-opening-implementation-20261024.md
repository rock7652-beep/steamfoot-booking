# 美業收費設定與開店引導：本機階段實作

基礎版本 6092de9111ec5f778d2f003c49657c4c073339d4，worktree /tmp/steamfoot-beauty-integration。此文件說明尚未部署、尚未接通完整儲存的階段成果，不代表可以正式上線。

## 已實作

- 實際 React 收費元件 BeautyChargeEditor，共用 RightSheet，桌機寬 640px、高上限 690px，手機依既有共用骨架滿版。
- 類型／服務、名稱／價格、體驗價／分鐘並排；技師桌機三欄、手機兩欄，維持 44px 操作高度與 16px 輸入字級。使用呼叫端資料，不新增讀取請求。
- 單次 sessions=1，體驗價格空白不提供、0 為免費，體驗分鐘空白沿用服務時長，整理時間沿用服務。
- 多次 sessions>=2，價格代表方案收款金額，不乘以次數；不顯示、不傳送、不接受體驗欄位。類型切換以不同 React key 避免非受控欄位值互相挪用。
- 下拉僅啟用服務，技師僅啟用且具該服務資格者。切換服務清空勾選；驗證重複技師、資格、服務與門市。這是本機輸入驗證，不能替代未來後端授權。
- 非同步送出鎖與關閉／未儲存提示。可注入正式儲存 port；未支援方案專屬技師時會在呼叫 port 前擋住。現階段呼叫端不提供 port，只在記憶體核對摘要。
- 首頁與收費方式串接八步引導。只使用已授權且已提供的資料，不增加資料庫讀寫；無權限讀到的資料不當成不存在。已有資料不標記成開店驗收完成。
- 新入口以 NEXT_PUBLIC_BEAUTY_SETUP_REVIEW=1 控制，預設不啟用；未變更任何環境變數，既有收費功能保持原狀。新入口是「新版收費設定核對」，不是已接通儲存的正式替換。

## 仍未完成、不能宣稱已支援的部分

1. 方案專屬 technicianIds 的持久化、同店與服務資格的後端授權／競態檢查。不得沿用舊 native-plan qualification 寫入技師.serviceIds 來假裝限制方案，否則會改動其他收費的服務資格。
2. 單次目前以 BeautyService.price/trialPrice/trialDuration 保存；新 UI 有獨立收費名稱。需確認一個服務是否允許多個單次收費，以及名稱保存位置。不能以新名稱偷偷改服務名稱。
3. BeautyPlan 僅 price/sessions/serviceIds 等既有欄位，沒有技師限制。若增加限制，需設計既有方案「未限制」與新方案「至少勾選一位」的差別，不可把空清單自動解讀成全選。
4. BeautyCard 等購入快照的技師適用規則與相容策略；既有卡不可默認追溯套用新限制。
5. 選技師限制須實際接入後台／會員／公開預約、多人分配、改期與時段查詢；資格、排班、計酬、位置與時間仍需取交集，不能只在 UI 過濾。
6. 八步目前是依現有資料產生的核對導航，不是完整自動進度精靈。店家資料、完整每週／例外時間、權限、全服務可預約性仍待權威唯讀檢查；不提供「全部完成」或自動開放預約。尚無草稿持久化、跨頁未完成提示或登入提醒。
7. 無 BeautySetting 時 selfBooking=true 的既有行為未改動。新店開放／既有店不回溯的策略仍待獨立設計。
