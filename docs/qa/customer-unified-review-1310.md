# #1310 顧客詳情與體驗收款驗收

## 範圍

- 預約詳情逐人體驗收款、本人方案與顧客資料。
- 顧客清單與原完整詳情路由共用同一份顧客內容。
- 延長到期、調整堂數、補登在方案的管理區就地展開。
- 新增欄位密度：收款金額／付款方式限寬並排；寬容器備註／提交並排；顧客編輯較早雙欄；基本資料寬容器雙組呈現。

## 暫時入口

`/preview-review` 只在原 #1310 Vercel Preview、原隔離 Supabase 專案、停用公開申請且存在有效期限設定時可用。其他環境回 404，Credentials provider 在查資料前拒絕。

使用者已授權暫時存取。伺服器只保存 256-bit 隨機存取碼的 SHA-256；連結使用 fragment，點「進入測試店」即先移除 fragment，再經 Auth.js 原生 CSRF 與 Credentials 流程建立登入狀態。禁止把存取碼／完整連結寫入此文件、PR 或 git。

只解析既有 `staging-user-owner`、`staging-staff-owner`、`staging-store`／`staging`，且必須為 ACTIVE OWNER；沒有新增／重設帳號或密碼，沒有 ADMIN 權限。沿用既有登入紀錄與 server action 權限檢查。

JWT 保留伺服器私有的授權版本與絕對到期時間；每次 auth 檢查原分支、資料庫隔離、有效期限、授權版本與當前 staff 狀態。更換設定、移除設定、到期、移動 staff、改角色／帳號狀態均使登入失效。Session 只公開測試店範圍，店別清單及跨店讀取／寫入／切換皆限制同一店；忽略先前店家檢視 cookie。最長 23 小時，不因 session 更新延長。

撤銷：移除或更換本支線的 `CUSTOMER_REVIEW_TOKEN_SHA256`。到期後入口自動失效，正式環境從不啟用。
