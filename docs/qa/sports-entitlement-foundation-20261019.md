# 運動權益基礎實作與驗證

此為第一階段歷史紀錄；後續排課、點名、表單接線與最新驗證狀態見 `sports-card-modes-implementation-20261020.md`。下方「接續範圍」描述第一階段結束時的狀態。

基準 main `8d717d5dc45da6fbd4e2984afea48165140281b3`；實作位於獨立分支 `fix/sports-item-and-universal-cards-20261020`，與 #1307 分開。本階段不改介面、不合併、不部署、不操作正式資料。

## 已實作

- 方案、訂單與課卡增加 `sportsMode`、`sportsSubjectId`、`sportsCost`。模式為 LEGACY／ASSIGNED／OPEN。LEGACY 保留原方案與課程模板限制，不把空白適用課程視為新通用卡。
- 後台結帳將同一份權益快照寫入訂單與課卡。會員送出購買時保存方案權益；核帳時從訂單複製，不重新讀取現有方案的權益。
- 共用 `resolveSportsEntitlement` 在一般預約交易判斷模式、項目與扣抵。ASSIGNED 使用購入課卡保存的扣抵數量；OPEN 使用本堂規則；兩者不能互用。原成員、到期、額度、容量、店家與角色檢查保留。
- 取消與點名沿用預約已保存的 `pointCost`。新產生缺課補課卡保留原權益及較窄的原課程限制；指定課補課保留原實扣數量。
- `scripts/sql/sports-entitlement-candidate.sql` 是新增欄位與一致性約束的候選，未加入自動 migration 目錄。沒有轉換舊卡、修改餘額、重算歷史或變更角色權限。尚未套用正式環境，不能直接將本程式部署至缺少欄位的資料庫。

## 本機驗證與證據界線

- 7 檔 81 項通過：權益判斷、隔離欄位變更、共卡預約交易（含新增模式案例）、有限批次分配、永久課容量、設定重送收據、計酬回歸。
- 另 1 檔 3 項結帳服務測試通過：LEGACY／ASSIGNED／OPEN 皆核對實際 create 參數，確認訂單與課卡保存相同快照。合計 8 檔 84 項。
- 因本階段也保存新補課卡權益，追加缺課補課、更正、學員補課及教師缺席還點回歸，4 檔 43 項通過；總計 12 檔 127 項通過。
- 候選 SQL 已在記憶體隔離 PostgreSQL（PGlite）實際執行。三個最小表的歷史餘額保持 17，舊列讀取 LEGACY；無效模式、遺漏項目或扣抵、跨單位不一致、重跑候選均拒絕。
- PGlite 證據只涵蓋候選 DDL 與約束，並非正式完整 schema、正式應用角色、RLS 或真實購買交易驗收。購買服務與預約交易證據使用合成資料及 mock 相依。
- `course-checkout.pg.test.ts` 15 項因未設定專用測試資料庫而略過，沒有連線正式庫補跑，也不計入通過數。
- 變更 TypeScript 檔的 ESLint、`git diff --check` 與完整 TypeScript `tsc --noEmit --incremental` 通過。首次檢查發現既有規則讀取型別為字串，已在共用判斷入口明確核對 ASSIGNED／OPEN 後重新完整檢查通過。
