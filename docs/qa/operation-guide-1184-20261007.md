### 隔離與通知的證據分層

1. `scripts/ci-migrate.mjs` 對本草稿分支的 Preview 加入前置檢查：`DATABASE_URL` 與 `DIRECT_URL` 都必須符合既有隔離專案，否則在 build 查詢前失敗。共用 `scripts/course-preview-scope.mjs` 驗證直連 hostname，或 Supabase pooler hostname 加上精確專案 username。只辨識連線目標，不輸出連線字串或秘密。
2. 已部署 build log 顯示 `[operation-guide-preview-preflight] isolated_database=true`，並顯示 `recovery_skipped_outside_production`。這是本輪隔離檢查與正式 migration 跳過的證據，不能解讀成已執行正式 migration 或驗證全部 schema。
3. `src/__tests__/operation-guide-preview-isolation.test.ts` 涵蓋兩條連線的允許／缺漏／不符、其他分支不受影響，以及三套業務 client／schema 的連線來源。這些測試不連線、不遷移資料庫；真實 UI 及下方唯讀核對另記。
4. LINE、Email、Messenger 的 Preview 外發阻擋已由程式及測試核對：`runtime-env.ts`、`line.ts`、`email.ts`、`messenger.ts` 與 `preview-external-integration-isolation.test.ts`。LINE 的另一個指定課程驗收分支例外不適用本草稿。
5. 本輪沒有刻意呼叫 cron、提醒觸發器或通知重送；沒有真實 LINE／Email／Messenger 送達測試，沒有實際金流。安全預覽與帳務記錄不能當作外部送達或實際付款證據。

### 普通人員的實際權限驗收

前段以另一個門市測試帳號登入曾顯示密碼錯誤；其後按使用者明確選定的既有運動店 STAFF 帳號，透過安全表單成功登入。實際網址位於該測試店的 `/s/.../admin/dashboard`，頁面身分顯示「門市人員」。沒有重設密碼、建立帳號或更動角色／權限。

- 側欄沒有「操作與登入紀錄」；直接開啟已知 HQ 稽核網址會安全返回自身門市首頁，登入仍有效，未看到稽核資料。
- 全分類指南搜尋「操作與登入」及「延後退款」均為 0 篇；收款更正關鍵字仍可找到有權限的 O05 說明，但 I11／I12／O09／O10 的完整題目與操作內容不出現。O08 的一般查單教學仍可讀取。
- 原有合成銷貨的選單只有編輯、列印、收付款紀錄，沒有退貨／退款、作廢銷貨或查看稽核紀錄。
- 收款列的更多操作只有列印，沒有更正付款方式／作廢收款。
- 無成本權限時不顯示銷貨報表分頁；具收貨權限仍看到進貨分頁。據此將 O08 的報表權限及 O01 的進貨財務資料用語補明，不改任何功能權限。

以上只涵蓋成功登入的運動店 STAFF 與前述 HQ ADMIN。另一門市的 STAFF、Manager、Owner、無 audit.read 的 HQ 及全部權限排列未一併列為已驗；沒有建立其他角色來製造結果。
