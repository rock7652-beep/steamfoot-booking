# 銀百合教學項目、購買方式與體驗排課修正

## 使用者回報與確認

銀百合：教學項目與老師授課設定名稱不一致；「舞蹈(常態)-10堂」選顧客可購買後仍僅後台指派；新增體驗排課沒有帶入單次方案的體驗資料，也無法直接填姓名電話新增學員。

唯讀正式資料：教學項目已改名但 CourseTemplate 名稱保留舊值，例如基礎課程仍為現代；同一項目存在舊 sports_rule 與目前 sports_item。指定十堂方案為LEGACY、chargeSettings=null、10堂／5800元／90天，customerPurchasable=false。單次「舞蹈(常態)1.5小時」體驗480元、trialDuration=null，應沿用一般90分鐘。

## 修正

- 原生運動老師端從 MusicSubject 顯示目前項目名稱，以本店 canonical sports_item 為目前項目；保留歷史 ID、資格、費率與課次，已選舊資格標為歷史項目。音樂與其他模組呈現不變。
- 重現舊方案僅改購買方式時，被新收費授課人員必填阻擋。既有LEGACY且無chargeSettings者保持null，購買方式從已選草稿送出；後端沿用既有templateIds與完整快照，不進入重新設定全體資格的舊流程。新建、缺快照與有明確新版設定的流程仍保留原檢查。
- 體驗排課預設新增體驗學員，輸入姓名手機；可切換既有學員。選單次收費後帶入體驗價與體驗時長（空白沿用一般時間）；0元保持免費，未設定體驗的指定項目明示阻擋。手機送出按鈕不覆蓋末端費用欄。
- 收費選擇在後端重驗。新體驗者交給既有 createCourseSchedule 的同一交易：customer.create／read、手機查重與可視範圍、顧客上限、建檔稽核、課程／場地／教師／容量檢查及體驗預約。運動規則只在經驗證的單次體驗學員名單存在時延後建檔，避免重複加入學員；一般指定課仍禁止空名單。
- 體驗名單指紋與 participantKey 支援相同請求重放；同鍵異名單拒絕。多人同手機資料需核對，不任選第一筆。沒有正式新增顧客、課程或預約作測試。
