# 美業收費與技師限制：後端設計草案

本機原始碼查核，基礎版本 6092de91。未連線任何資料庫、未查實際筆數、未變更 schema、未產生或執行 migration、未部署。此為實作設計，非已上線規則。

## 建議採用的資料語意

- 單次先沿用「每個服務一組單次價格＋選填體驗價／分鐘」，不在未經確認下新增同服務多組單次收費。收費名稱沿用服務名稱呈現；不能將收費名稱改寫回服務名稱。核對元件的自由名稱欄位須依此調整或待獨立收費模型確認。
- 多次價格為整包收款金額；沒有體驗欄位。新建多次只選一個服務；既有多服務方案保留既有適用清單，不自動縮減。
- 技師服務資格（BeautyTechnician.serviceIds）不變。每個收費方式另保存「限制模式＋允許技師 ID」，不能以修改技師資格代替。
- 明確區分 LEGACY_UNRESTRICTED 與 SELECTED。舊資料維持前者；新設定必須 SELECTED 且至少一位。空名單不能自動代表全部技師。
- 單次與體驗依確認介面共用一份允許技師清單；多次每方案各有清單。單次限制的儲存位置與獨立收費模型一起確認，初期可放服務收費規則，但需與服務資格分開。
- 售出多次方案時，在 BeautyCard 保存適用技師規則快照，與現有 serviceIds／價格快照同時建立。後續改方案不追溯修改既有卡。未設定快照的舊卡維持原行為。
- 禁用、失去資格或不在排班內的技師，即使出現在購入快照中，也不得被安排；提示聯絡店家處理，不偷偷換方案或放寬限制。

## 寫入流程（未接通）

1. 使用既有 beautyManager + 權限與功能檢查，確認門市、可編輯收費資格及目標 revision。前端能力開關不是授權依據。
2. 驗證服務為同店啟用項目；技師 ID 不重複，全部同店、啟用且具該服務資格。僅限收費技師限制，不順便增刪資格。
3. 同交易保存價格／體驗設定或方案，以及允許技師，使用既有 requestKey command 防止重複提交。讀取快照後若 revision／資格已變，拒絕並要求重新核對，不自動重試。
4. 回傳權威儲存結果，刷新對應 catalog；保留未確認的表單草稿，不能顯示假成功。
5. 現有 saveBeautyNativePlan.qualification 會寫技師 serviceIds；新流程不得呼叫該分支。既有流程的轉換需另有相容測試。

## 預約與改期

來源：src/server/beauty/booking.ts 的 findAllocation/assertCard、src/lib/beauty/allocation.ts、src/server/beauty/availability.ts，以及 src/server/beauty/commerce.ts 售卡快照。

- 在進入多人配對前，為每位服務者取得已授權的收費規則（單次／體驗或已購入卡）。無權限卡不能用來推知技師或時段。
- allocateParty 的每人候選技師 = 收費允許 ∩ 技師服務資格 ∩ 啟用 ∩ 性別／指定條件 ∩ 排班 ∩ 計酬有效 ∩ 無衝突；位置仍核對完整服務及整理時間。
- 允許名單必須屬於每人條件，不能用整組名單聯集，避免同行者借用另一人的資格。
- 查時段與最終建立預約都使用同一條規則；交易中再次驗證，不能只信任前端 expectedArrangement。
- 後台／會員／公開入口／同行多人／指定技師／自動分配／改期都必須一致。無符合技師時回傳無可用時段或可理解的衝突，不回退為所有技師。
- 既有預約目前保存價格、時間、技師等快照。保留既有紀錄；改期時應沿用預約的收費身分與購入卡規則，同時檢查技師當前資格及排班。單次既有預約是否保存獨立收費限制快照，需列入資料設計，不可默認套用最新價格或時長。

## 離線測試清單

- 新限制技師不可跨店／重複／未啟用／不具資格；revision 衝突與重複 requestKey。
- 價格不乘次數；體驗價空白／0、分鐘空白／指定；多次拒絕體驗欄位。
- 修改方案不變更其他方案、技師資格或舊卡快照；既有多服務方案不被縮成一項。
- 每人不同方案的交集配對、指定不允許技師、無符合技師、技師休假／停用、整理時間占用、並發資源衝突。
- 查時段與送出／改期結果一致，前端竄改或過期 expectedArrangement 被拒絕。
- 未完成權威可預約性檢查前，開店引導不標記全部完成，也不自動打開 selfBooking。
