# 課程學員共用家長聯絡電話：本機候選

基準：`236d637d`，本次變更仍在工作區，未 commit、push、部署或執行正式 migration。承接本聊天的課程名額與四模組後台補登修改，不覆蓋先前成果。

## 行為與範圍

店長在課程學員建檔、排課快速建檔、名單新增體驗客及音樂體驗排課，沿用姓名與電話欄位即可讓不同孩子共用聯絡號碼；依使用者最新要求，移除新增的共用電話選項。系統在店家鎖內自動處理不同姓名的電話重複，不要求店長選擇資料模式。學員 ID、方案、名單、扣堂及出席各自保留；搜尋共用號碼列出各孩子，依姓名與 ID 選擇。相同姓名與電話優先使用已有資料；不同姓名不會默默沿用第一筆學員。

本批建檔候選不建立家長帳號代管權限、不按電話合併學員、不改寫既有資料或恢復通知。後續使用者已確認採「同電話集中查看」，入口核對及待實作範圍見 [課程 LIFF 同電話集中查看](course-phone-group-liff-20261110.md)；不另建大人顧客。家長聯絡電話不能單獨作為登入、Google 或 LINE 身分證據。原「缺少店舖資料」來源是登入店別檢查；未取得正式請求日誌，不能把此訊息歸因於電話重複或宣稱已修復。

## 資料庫變更與順序

核心 Prisma migration：`prisma/migrations/20261110082629_course_family_contact/migration.sql`。名稱由 Supabase CLI `migration new` 產生，SQL 放在此 repo 的核心 Prisma migration 路徑；不另加至課程資料庫或重複登記 Supabase migration history。

- 新增 `Customer.contactPhone`。聯絡專用學員的 `phone` 為空字串，聯絡號碼存在獨立欄位；不捏造假手機、不更改 phone 的非 NULL 型別。
- `uq_store_customer_phone` 改成非空個人手機的部分唯一索引，保留原本跨店與同店唯一語意。另一個部分唯一索引保留舊空白手機記錄的一店一筆限制。
- 聯絡電話有格式檢查。資料庫拒絕給「沒有個人手機、只有聯絡電話」的學員寫入 userId、Google ID、LINE ID 或 LINE 綁定碼。已連結身分的既有學員也不能從後台直接轉成聯絡專用資料。
- 建檔入口送出穩定 requestKey，僅作內部重送識別，不新增使用者欄位；自動判定為共用聯絡電話的新建請求需要此識別；與學員及 AuditLog receipt 在店家鎖內同筆提交。重送回原 ID，改姓名重用同一請求拒絕；SELF_ONLY 建檔保留可見管理者歸屬。

此候選讀取新欄位，正式啟用須先審查並套用指定核心 migration，再發布對應程式與生成的 Prisma client；尚未執行。不得直接執行全量 pending migrations。遷移前另核對實際索引定義、依賴及資料庫備份；本機測試不是正式資料盤點。

回復：不得在已有多筆聯絡專用學員後直接恢復完整的 `(storeId, phone)` 唯一索引，亦不得為回復刪除或合併孩子。若正式啟用後需回復，先停用新建入口、保留資料，另訂相容回復；尚無聯絡資料時才可在核對後撤回索引／欄位變更。
