# 運動新版新店引導修正與全新空店驗收

## 問題與修正

新店原本先設定收費方式、再新增教練，但收費方式要求至少一位教練，因此會卡在3/6並顯示英文陣列驗證錯誤。另候補未啟用仍預填5人，建立第一堂開放選課會被後端拒絕。

運動原生新版現在依序：營業時間、空間、教學項目、教練基本資料、收費方式與授課教練、第一堂課。第四步只要求至少一位啟用教練；第五步仍要求有效收費與授課資格，不因提早完成教練基本資料而放行未具資格的排課。既有缺資格的收費會導向補齊，沒有開重複新增表單。

引導連結帶setupFlow=sports，彈窗步數與主引導同步；一般音樂及舊課程步驟不變。此標記僅影響步數顯示，不參與授權。引導中新增教練成功後關閉編輯器，透過既有SETTINGS_SAVED、storeId及權威readCourseSetupProgress更新進度；一般人員／音樂新增仍保留編輯器。沒有新增快取或放寬後端權限。

運動排課明確接收有效waitlistEnabled：未啟用時顯示0及「候補未啟用」，不可編輯；啟用時沿用店家預設人數。送出依有效開關產生額度；既有候補後端檢查保留。沒有自動啟用全店候補、改店家設定或清除原本預設。

## 界線

這是全新本機隔離服務的真實UI→action/API→PostgreSQL驗收，不是已部署Preview。僅本機測試工作樹加嚴格localhost QA入口adapter及Turbopack工作樹根目錄，實際引導／表單／儲存／排課檔案與修正分支逐檔hash一致。adapter、測試密碼、登入工作階段、任何正式連線都不納入修正分支。
