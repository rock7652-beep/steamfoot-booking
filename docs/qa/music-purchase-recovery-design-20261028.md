# 音樂購課結果不明與防重設計（待實作）

## 問題與現有證據

同一學員的購課可能因網路中斷而無法判斷是否已入帳。`assignCoursePointCard` 的交易會取得課程門市鎖，並以 `(storeId, requestKey)` 查既有 `CoursePurchase`；音樂原生收款再以 `CourseMusicTuition.checkoutFingerprint` 比對資料。相同 key、相同內容重試有防重保障；會員資料與課表名單兩個入口在關閉或重開後可能重新產生 key，跨重新整理及另一裝置沒有共用待處理狀態。音樂測試站使用固定 URL checkout，其他音樂店仍可能使用 Server Action，單改測試站 transport 無法保護全部入口。

「沒有查到交易」不代表失敗：原請求可能尚在網路途中、授權中或等待交易鎖，稍後仍可提交。現有訂單／卡／InventoryCommand 等只在各自交易中建立，沒有可否終止尚未抵達請求的完整生命週期。單純查詢、固定 UI 或儲存相同 key 都不能涵蓋跨裝置與晚到請求。

## 預計交易契約

1. 新版 UI 在送出支付前，以唯一 requestKey 註冊經驗證的購買意圖；寫入服務器的最小識別、店、學員、建立者、版本與收款日等必要狀態，原始帳號末四碼或完整表單不得寫入瀏覽器持久儲存。全部請求都重新核對身分、`wallet.create`、`transaction.create`、折扣權限、實際門市與學員歸屬。
2. 用資料庫唯一限制阻止同一 `(storeId, customerId)` 同時存在多個未結意圖；成功或安全取消後才允許下一筆。這容許店長依序連續購買六次，每次須先確認上一筆的結果。
3. 同一門市鎖下檢查意圖，將提交交易及意圖狀態變更放在同一資料庫交易；成功提交後返回既有購課／收款結果。重複 key 僅能讀取原交易；不同內容必須拒絕。需設計有版本的服務器端 keyed HMAC／等效方案核對規範化輸入，密鑰不進入瀏覽器或日誌；一般雜湊不足以保護低熵末四碼。現有 `checkoutFingerprint` 行為和資料保留亦須獨立檢視。
4. 意圖至少需 `PREPARED`、`COMMITTED`、`CANCELLED` 狀態；寫入錯誤若已證實資料庫交易回滾，可仍保留 `PREPARED` 待人工重試或取消，不能依網路斷線標記失敗。`COMMITTED` 應不可逆並連結權威交易紀錄。查無意圖、連線失敗或讀取不完整均只顯示「結果尚未確認」，不能允許默認重買。
5. 取消在同一門市鎖下執行：若已提交則回傳既有成功；否則先原子地標記 `CANCELLED`，後續晚到的購課請求必須在同鎖內拒絕。不可設計只清除前端狀態或單純 TTL 自動釋放。狀態查詢僅回傳使用者有權查看的最小資訊，不以 key 本身作為授權證據。
6. 重新整理／切換頁面時，瀏覽器僅保存必要的隨機 key 與安全範圍資訊；若瀏覽器資料不可用，應由授權的門市／學員待處理查詢找回。提交前意圖註冊的網路請求也可能根本未抵達或延遲抵達：當前分頁需在第一次送出註冊前持久保存 key，以同 key 查詢／重送註冊；本地儲存不可用時不可假裝可跨刷新復原。另一裝置無法事先知道「尚未抵達伺服器」的意圖，必須在流程與介面明確表達這個不可觀測邊界，不以查無放行或承諾絕對跨裝置防重。

## 舊版相容與部署

- 課程所有購買入口、音樂測試站固定 URL、一般 Server Action、課表及學員資料入口均須經同一服務端檢查；美業如透過共用 action 需釐清並保留其業務規則。舊分頁沒有意圖的購課請求應在任何收款動作前明確回覆更新提示，不能悄悄用舊路徑繞過；完成前不得開啟服務器強制。
- 先以可回滾 migration 新增表與索引，再部署具備讀取／註冊／取消能力的新版本；核對所有入口、舊頁面、任務／匯入和權限後，才啟用門市級強制與舊客戶端阻擋。對舊版正在途中的請求、滾回和資料庫故障，必須明確定義可見且不重複入帳的結果；功能不得以 fallback 降級繞過鎖或意圖。
- 不刪除、改寫歷史交易；不得將未有意圖的歷史訂單視作失敗。正式資料的 migration／強制啟用應另行驗收後安排，不在本文件中執行。

## 必要驗收

- 真實 PostgreSQL 併發：相同 key／同內容、相同 key／不同內容、同學員不同 key、不同學員、提交與取消競爭；核對至多一筆收款及一張卡，且帳務流水平衡。
- 故障注入：註冊請求未抵達、回應丟失、提交前中斷、提交後回應丟失、資料庫回滾、快取／投影失敗、取消後晚到、原請求等待鎖、隔日重試；不能自動重送收款。
- 重新整理、關閉重開、另一分頁／裝置、瀏覽器資料清除／不可用，以及服務重啟；對不可觀測的未送達請求維持明確待核對提示。
- 本店／跨店、停權、不同角色與折扣權限；不能泄漏客戶、金額或付款資訊。驗收學員頁與課表繳費、一般音樂店與測試站、共享 action 的其他模組及舊版客戶端。
- 桌機與 iPad UI，確認處理中／待核對／已完成／安全取消訊息、不可重複送出，以及連續六次已確認購課；查核每筆交易、卡、剩餘堂數與歷史紀錄。

## 本輪結論

目前沒有可安全直接重用的已持久化購課意圖或可靠取消屏障；在所有入口、跨裝置及舊版客戶端尚未設計完成前，建立未接上的局部表或前端防護會產生虛假的完整保障。此文件為具體設計與驗收清單，並非功能已實作、資料庫已遷移或正式環境已修復。
