# 進銷存測試版本

本分支新增獨立的單店進銷存。HQ 必須明確開通 inventory 功能；不因體驗方案或 SPA 示範店自動開通。不合併正式站。

## 已接上的功能

- 廠商基本資料、商品、庫存、進貨單、銷貨單、收付款、盤點與操作紀錄。
- 同品項可由不同廠商供貨，進貨時更新移動平均成本。
- 折抵金額、折扣百分比、贈品；贈品扣庫存並計入成本。
- 未付款仍異動庫存；真正收付款才連動現金收支。現金帳連動項目不可獨立修改、刪除。
- 同一對象可一次收付多張單；收款單保存每張單的收款後餘額。
- 姓名及電話即時搜尋、快速建立顧客，沿用全站重複電話驗證。
- 自取／寄送、寄送管道、顧客運費、寄送備註與內部備註。
- 商品期間彙總／每日明細；商品報表排除運費，包含贈品成本。
- 商品 Excel 輸出與盤點記錄；日期、記錄者、原數量、實際數量與差異。
- 顧客 A4 銷貨及收款明細不含成本和內部備註。

## 權限

沿用人員管理中的四個獨立權限：inventory.read、inventory.write、inventory.manage、inventory.cost.read。沒有成本權限時，伺服器回傳內容即移除平均成本和銷貨成本，並排除進貨資料。Boss／Manager／Staff 預設角色依討論留待下一步設定；此次不自動授權現有人員。

Excel 同時檢查 report.export 及 DATA_EXPORT 功能。關閉時隱藏按鈕，直接呼叫 API 也拒絕。財務人員既有現金收支權限仍可能看見進貨付款總額；正式權限驗收必須一起檢查現金收支及其他財務報表，不能只關閉進銷存成本欄。

## 驗證

- 帳務服務及既有現金帳回歸測試。
- ExcelJS 重新讀入輸出，驗證是實際 xlsx、一般人員沒有成本欄，以及以等號開頭的商品名稱仍為文字。
- JSDOM 互動測試：姓名／電話搜尋、權限隱藏、切換保留搜尋、數量欄保持同一 DOM 與輸入焦點，其他欄位不被重設。
- 隔離 Supabase steamfoot-preview 已套用資料表 migration。負庫存、超額已付及錯誤門市外鍵測試全部回滾；六張資料表已啟用 RLS，anon／authenticated 無直接讀寫授權。
- 新增程式 ESLint 檢查。全專案 TypeScript 檢查無進銷存程式錯誤，但仍有既有現金抽屜及 Messenger API 額外 export 造成的 Next.js 產生型別錯誤。6 個測試檔案共 40 項通過。完整 Next.js build 的編譯階段通過，但既有 cash-drawer/page.tsx 的額外 courseHome PageProps 不符合 Next.js page export 規格，建置型別檢查未通過；本分支不宣稱完整 build 成功。
