# 課程模組第一階段：課程設定與排課

本階段從 2026-09-15 已確認的互動示意進入程式實作。第一家目標為運動團課、自由預約、點數方案；音樂、期課、堂數方案、訂閱、候補、線上付款與薪資拆帳不在第一版。

## 本次完成

- 新增 COURSE 模組識別、專用後台 `/dashboard/courses`、側欄入口。
- 沿用 PageShell / PageHeader / RightSheet，月曆預設當月，選擇日期在同頁右側顯示。
- 空白日淡化但可排課；建立後導向實際排課日期並重新讀取資料。
- 建立教室與課程預設：名稱、時長、點數、容量、預設教室。
- 單堂或每週重複至指定日期。單一教室自動带入；多教室可調整。
- 實際課次保留名稱、點數與容量快照，不依未來課程預設改動。
- 後端驗證權限、具體店家、模組、教室、課程、在職教練的歸屬。
- 重複排課整批交易，衝突回報第一個日期；request key 防止重試重複建立。
- 資料庫排他約束保護同教室／同教練交疊，首尾相接允許。
- 專用 Prisma client 不宣告蒸足／SPA 的交易與預約模型。
- COURSE 店家後台暫時只提供已完成的課程頁，避免進入舊模組後台讀取。

## 驗證

- 8 個針對變更範圍的 Vitest 檔案，105 項測試通過：課程 action、日期、模組防火牆、既有 SPA 導覽、proxy、店家建立規則。
- TypeScript `tsc --noEmit` 通過，新課程檔案 ESLint 通過，三個 Prisma clients 可生成。
- 在本機 PGlite PostgreSQL 引擎執行完整新增 migration，驗證既有店家模組未改動、教室與教練排他約束、相鄰時段、跨店外鍵、時長限制、交易回滾、RLS。
- 以實際 React CourseWorkspace 建立隔離瀏覽器測試：改日期排課後清單／月曆更新、完整起迄時間、原地新增教室與課程、1024／768／375px 無整頁橫向溢出。
- 瀏覽器測試的 navigation 與 Server Actions 使用假資料；SQL 驗證是本機引擎。尚未進行真實登入 → Server Action → Preview DB 的整合驗收，不代表正式店家可用。

## 部署邊界

- 加法 migration：`20260915090000_add_course_scheduling`。不轉換、不啟用、不建立任何正式店家。
- 不更動現有 production migration allowlist。由既有發布程序另行審查並在隔離 Preview DB 套用。
- `course-prisma/schema.prisma` 僅用於 generate，migration 仍由主 `prisma/migrations` 管理。禁止對正式 DB 以此獨立 schema 執行 db push。
- 建店表單／驗證仍僅開放 STEAMFOOT、SPA。不能只將既有店家改為 COURSE 來驗收。
- 開放試營運前須完成 COURSE 顧客入口、背景工作隔離、試用店佈建與下列功能，且在隔離 Preview 店驗證完整流程。

## 下一階段

1. 點數方案的售價、可用點數、保留點數、有效期限與店長指派。
2. 共用學員：既有方案加人；未註冊者独立學員紀錄；已有帳號互相代約。
3. 顧客按姓名約課、整組席次與點數原子保留、防止同人同課重複。
4. 學員預約接入後，店長月曆顯示堂數／人次，顧客顯示本人藍點與共卡橘點。
5. 同堂課合併的我的預約、個別取消、店家預約／取消時間設定。
6. 出席／未到／更正、其餘全部出席、依店家規則結算與補課券。
7. 修改既有課程與課次、整堂停課返還保留點數與通知。

預約即減少可用點數，出席正式扣除且不重扣。第一阶段尚未建立學員預約模型，因此目前月曆顯示堂數，課次顯示人數上限；不以假人數填入正式元件。
