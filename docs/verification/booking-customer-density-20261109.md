## 正確入口與目前設計

使用者最後釐清的入口是「預約管理月曆 → 某一天 → 當日預約清單 → 體驗客的收款 → 預約詳情」。需要保留清單背景，並整理這個第一層預約詳情。先前獨立付款視窗的方案已取消，舊 collection-focused／collection-purchased 截圖不代表目前設計。

- 當日清單維持掛載、搜尋及捲動狀態；詳情疊在上方，被覆蓋的清單 inert。
- 預約詳情每人一個緊湊區塊，姓名、同行標記、到店狀態、本次服務與主要操作對齊。次要操作收進更多選單；電話及完整個資需要時才開啟。
- 每位顧客的確認收款表單在自己的區塊內展開，不另開獨立付款視窗。收款成功僅更新該人並收合表單，其他同行人不變。處理中防重複，失敗保留輸入與錯誤。
- 已完成者顯示實收金額與付款方式；體驗已收款完成者直接顯示「＋新增方案」，其他次要操作維持更多選單，表單仍在同一詳情內展開。
- 方案查詢比對已知錢包 ID，新增加的方案在本人區塊多顯示一行「新購方案・剩餘堂數・下次使用」，不是把既有方案當成新購。新購摘要使用次要灰字，與本次付款資訊分層。待付款明示尚未開通，讀取失敗提供重試。
- 收款即完成服務；方案扣堂仍在原後端權威交易成功後更新，目前餘額含預留堂數，不提前減少。購買不會自動套用本次或扣新方案堂數。新購方案資格的全面後端限制不是本次 UI 驗收範圍。
- 詳情固定上緣與外框，長內容在內部捲動；保留已確認的顧客資料固定高度。主要按鈕觸控空間維持原尺寸，不以縮字增加密度。

## 保留的其他調整

- 月曆上方為單行「本月預約筆數／人次、已完成、待服務、取消筆數、未到人次」。依整個選取月份計算，不受清單篩選影響；取消筆數指整筆預約取消，同行人個別取消不當成整筆取消。
- 顧客管理及預約內顧客資料共用元件，固定摘要與總覽／預約紀錄／消費紀錄／基本健康資料分頁。方案數字分組、日期與欄位對齊，紀錄翻頁保留狀態，失敗重試同頁，不同顧客資料隔離。
- 顧客視窗桌機／iPad 固定 min(640px, 100dvh - 48px)，切換分頁不改變寬高或位置，手機保留共用全螢幕處理。
- 後台指南 C04、D03 同步分頁與方案摘要，未新增前台指南。沒有資料庫 migration、通知設定或 Cloudflare 變更。
