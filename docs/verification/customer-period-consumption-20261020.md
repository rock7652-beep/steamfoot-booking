# 顧客經營：期間消耗統計

## 範圍與入口

- `/dashboard/growth/consumption`；店家及 HQ 路由前綴沿用 DashboardLink，與顧客關懷、數位管家名單並列。
- 適用目前啟用的蒸足及課程（運動／音樂）模組，共用畫面、分開讀取業務資料。
- 本月、上月、近 30／90 天、自訂日期；收費方式、姓名／電話、數值上下限（AND）、高低排序、前 N 名、每頁 50 人、CSV。
- 顯示消耗次數、依店家現有及歷史方案單位顯示堂／格／點、消耗金額、實付金額、目前方案餘額與到期日。顧客連結沿用各模組既有詳情入口。
- 顧客欄後顯示「所屬店長」，使用顧客目前歸屬，未指派顯示「未指派」；CSV 同步帶出。人員關聯同時比對店家，不顯示外店人員名稱，沿用既有顧客可視範圍。
- 「篩選」視窗可選全部店長、指定店長或未指派；與期間、收費方式、數值條件同時生效，排序、分頁及 CSV 保留條件。選項只來自目前門市及員工可視範圍，直接指定外店或不可見店長會被後端拒絕；選其他店長不能擴大 SELF_ONLY 可視範圍。
- 沿用既有低頻顧客功能；不提供活動建議、通知、優惠發送、兌換管理或成效追蹤。

## 清單密度修訂

- 主畫面改為可換行的精簡工具列，移除大型篩選卡片、上下堆疊的欄位標籤與清單前的長說明。
- 排序項目及方向合併為單一下拉選單；數值條件用「項目下拉＋最低／最高」呈現，不同統計項目不再各佔一整組表單。需要多條件時才新增條件。
- 數值、曠課／請假與前 N 名改用既有 ModalPanel 按需開啟；自訂日期也在同一視窗編輯，套用後自動回清單，即使已有條件也不展開整頁。
- 使用既有視窗焦點、Escape 與捲動管理；返回清單或旋轉尺寸保留未送出的篩選草稿。字級保持 14px、主要控制保持 44px，不以縮字取得密度。
- 姓名與電話放在同一可操作區，精簡清單列高；人數、日期與匯出整合成一列，計算說明移到清單後。
- 真實元件合成資料預覽：1366×900 的表格由畫面 y=682 提前至 y=266；工作區可視清單占比桌機約 82%～85%，iPad 約 78%～84%。此占比以工作區起點至視窗底部為分母，包含預覽外框時整體占比不同。
- 自動檢查要求桌機／iPad 清單至少占工作區剩餘可視高度 2/3，並額外驗證項目下拉、多條件、視窗關閉／旋轉保留草稿與套用後回清單。手機及 iPad 篩選視窗另有截圖。

## 計算口徑

1. 實際扣堂／格／點或已完成的付費服務納入；同一筆服務多種扣除只算一次。只有購買方案不增加服務消耗次數。
2. 課程使用目前已扣除的預約狀態（出席、曠課、團體請假扣除）與當時課卡單位／扣額快照。還原待點名、取消免扣不計；共享卡歸實際預約顧客，不歸購卡者，也不複製給全部共卡成員。
3. 蒸足使用完成的 WalletSession 及有效服務收款；多人預約依 BookingParticipant 個別狀態及本人扣堂／收款歸戶，避免重複算父預約。已完成者不必等其他同行處理完才列入。
4. 預設包含曠課及團體請假扣除，可選擇排除；此選項只影響服務消耗，不抹除已發生的收付款。
5. 消耗依服務日期、實付依收款日期計算，使用 Asia/Taipei 日期邊界。蒸足純日期欄位使用 DB date；課程使用 timestamptz。
6. 實付是有效服務／方案收款減去期間退款；不含待收款、作廢、紙本移轉及手動調整。退款可能使期間實付為負，可設定負數範圍。現金帳手動收入、零售、場租不是本報表服務／方案收款來源，不納入。
7. 金額消耗使用實際服務收款，非方案定價折算。現行有效模組沒有儲值扣款資料來源，本功能不建立儲值模型。消耗與實付可能對應同一筆服務，不可相加。
8. 指定收費方式後，消耗、付款與目前餘額全部依該方式計算；只列持有該方式方案或期間有該方式紀錄的顧客。不同方式的每點／格價值可能不同。
9. 零消耗顧客可列入；排除合併來源、停用帳號及期間結束後才建立的顧客。無顧客 ID 的同行者不依姓名猜測歸戶；無服務日期的紙本歷史不推定當期消耗。舊整組紀錄仍歸既有記錄的顧客，不回溯拆人。
10. 目前方案餘額為查詢時有效方案剩餘，非期間末餘額，也不是扣除預約占用後的可用額；共卡另有標示，不可跨人加總。

## 權限與匯出

- 查詢／直連要求 `customer.read`、`booking.read`、`wallet.read`、`transaction.read` 與目前店家的 `customer_care`。
- CSV 額外要求 `customer.export`、`data_export`，每次重查授權及店家；不接受客端 storeId。
- 沿用 active store、授權母子店檢視與 SELF_ONLY 員工可視範圍；HQ 全店模式須先選具體店家。
- SQL 參數化，排序欄位固定白名單，同值以姓名／ID 穩定排序；單次查詢同一份結果提供總數及分頁。
- CSV 匯出所有符合排序與前 N 名條件的結果，不只目前分頁；最多 10,000 人，超過明確拒絕，不靜默截斷。包含期間、篩選條件、排序及目前餘額標示，處理 CSV 引號、換行與試算表公式注入。
- 不新增 schema、不執行 migration、不寫店家業務資料。此實作支線關閉 Vercel 自動部署，不合併正式站。
