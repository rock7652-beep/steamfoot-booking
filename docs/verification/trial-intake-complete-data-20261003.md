# 體驗申請表修改清單

## 申請與體驗規則

- 體驗不限門市數，每間門市分開申請；按門市間數服務與收費。
- 同品牌可共用聯絡人、Email；同門市補件保留申請編號。
- 新增「申請另一間門市」，保留聯絡資料、重設門市與 LINE／初始設定資料，未送出草稿先確認。
- 每店完成基本設定與操作教學後開通，再起算各自 30 天體驗；不必等全部課表與方案建檔完成。
- 對外文字為「最多 3 位後台使用者」，前台教練 LINE 身分分開。沿用既有使用者限制，這次不更動方案／權限模型。

## 表單欄位

- 品牌、其他申請門市、希望網址英文名稱 Slug（butler 為示例；只收希望名稱、不自動佔用）。
- 其他後台使用者姓名與 Email。
- 共用 LINE／共用門市／LINE 管理員聯絡方式。
- Provider、Messaging API Channel、LINE Login Channel 各自 Admin 邀請進度：未邀請、已邀請待核對、尚未建立、需要協助。
- 教練、教室、課表、方案、預約規則：提供摘要／附件、不需要、需要協助、待提供。
- 現有學員是否需匯入；由服務人員另提供格式。
- 最多 3 個 PDF、PNG、JPG、xlsx、docx、CSV 附件，合計 2 MiB。

## 收件與相容性

- 新欄位與附件沿用受保護 TrialApplication JSON payload；不需要資料庫遷移。
- 舊申請補件預設新欄位，維持 token hash、修訂衝突與防重送。
- 同 Email 每小時限制改成同 Email＋同店名；不同門市不互相阻擋，仍保留 IP 限流。
- 通知收件人維持 steambutler500@gmail.com；LINE 授權對象維持 rock7652@gmail.com。
- 現有 Google 收件程式相容：在「待補資料」欄保留待核對清單＋設定摘要，不修改原表頭或部署。摘要限 2500 字，詳情／檔案留在總部。
- Sheet 與 Email 僅列附件檔名，不包含檔案內容、管理員邀請連結、補件 token 或密鑰。
- 附件下載需 HQ ADMIN＋staff.manage，回傳 attachment／no-store／nosniff，不提供公開下載網址。

## 驗收

- 基本收件、同列補件、寄信失敗重試、舊 payload、Slug、Admin 進度、附件格式／大小／權限及原 Google 接收程式回歸測試。
- 正式站未合併；Preview 不能當作實際寄達官方信箱。

## 簡化申請與首次教學

- 首頁改為先填基本資料、確認 LINE 串接、視訊完成第一筆預約。
- 第四區改為視訊操作教學；詳細設定放入選填收合區，附件選填，原有資料與補件相容。
- LINE 設定協助者聯絡方式選填；只有共用 LINE 才顯示共用門市名稱。
- Admin 個別進度保留在選填收合區，內部仍逐項核對；邀請帳號維持 rock7652@gmail.com。
- 最後確認僅呈現基本收件狀態，完整核對清單仍保留總部。
- 收件成功說明確認串接與安排視訊的下一步。
- 教學前準備電腦／iPad 與手機；教學先排一堂課、手機預約、後台報到，再由店家獨立操作一次。測試課程及預約由服務人員核對後清理，不自動刪除。
- 不增加教學時段欄位或自動建立測試預約。

## 第一區收合與錯誤導引

- 第一區預設顯示門市名稱、類型、聯絡人、電話、Email、Google 地圖六項；品牌、其他門市、希望網址名稱、其他後台使用者收入「補充資料（選填）」。
- 送出統一由既有 schema 驗證，保留必填、Email、網址與 Slug 檢查；不因收合略過資料驗證。
- 首筆錯誤自動開啟所有上層收合區、捲動及聚焦對應欄位；摘要欄未顯示時帶到提供方式，附件錯誤帶到上傳欄。
- 仍保留原申請與草稿，收合不清除任何欄位。
