# 連續切月預讀補修

使用者確認課表最後會出現，但希望切換像蒸足一樣不必等整塊載入。#1525 處理快照期限與初始月份，沒有處理相鄰月份準備太晚、只有一層範圍，以及 FIFO 淘汰的問題。本次以操作後完整課表出現為證據，不將 HTTP 200 當改善完成。

## 修正

- 本月畫面先顯示，250ms 後以最多兩筆並行只讀查詢，準備前後各兩個月（含本月維持五筆快照上限）；兩方向不用串接等候。
- 跨日期／scope 的 effect 重建仍共用同一 hook 的在途計數，避免快速切換時突破並行上限。編輯、隱藏、離線及輸入保護保留；剩餘工作在取消後不再啟動。
- 預讀已有顯示快照的月份不因15秒freshness到期就重複下載；真正切月仍重新核對。snapshot 重用更新 LRU 順序，避免最初月份被遠月預讀淘汰。
- 顧客預讀的預設1.5秒／單筆節奏保持；未更動同步、付款、扣堂、名額及後端權限規則。首次極快點擊或超出準備範圍仍可能等待，不承諾任意月份無網路延遲。

## 可重現證據

相同 Chromium 合成資料、每次 API 延遲650ms，進頁1000ms就點「下個月」：原版失敗 `neighbors not preloaded`；本版音樂／運動／美業皆完整課表出現，未等點擊後的模擬網路完成。使用 scripts/qa/calendar-customer-preload-browser.mjs --fast-switch --edge 重現；可加 --retained 驗證快取期限後的操作。
