## 回退方法

- 清理未啟用時，舊表資料未刪。出現問題先保持清理關閉，回退到已確認的前一個應用部署，保留所有新增欄位／防重資料／索引，避免 destructive down migration。
- 舊應用仍依 handledAt 工作，新應用的已讀操作只寫 readAt；回退時已讀提示可能回到舊狀態，需要核對，不能承諾畫面標記完全一致。
- 已物理刪除的通知無法靠應用回退恢復；須使用已驗證的備份／選擇性復原方案，不能還原整個正式資料庫覆蓋上線後的新預約或帳務。
- 未進行正式回退或正式備份復原驗收。本輪只提出方法，不把方法視為成功證據。
