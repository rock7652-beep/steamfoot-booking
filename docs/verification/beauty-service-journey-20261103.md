# 美業合併主服務與加做混合支付（本地候選）

版本基準 f64aabb7；在本地修改，未推送、未建 PR、未部署或遷移正式資料庫。沿用本聊天已確認規則；先前「加做可扣加做方案／組合方案」提案已被取代。

## 規則與介面

- A、B 是主服務；會員本人持有不同主服務的不同有效多次方案時，才能選同次依序完成。重複購買相同服務方案不開放重複主服務。體驗、公開試約與身分後補同行者維持原流程。
- 1、2、3 是各服務獨立設定的加做，放在所屬服務段下，單次計費，增加該段時間；不建立加做方案或扣主服務方案來支付加做。
- 單服務表單維持原貌；有其他適用方案才顯示「合併其他服務」，選取後顯示方案與加做；需要時才勾選「分別安排技師」。預設所有段同一技師；不同段可分別指定或自動安排。
- 技師、位置、營業時間、租借占用與顧客占用都按各段核對。現有顧客占用包含整理時間，因此下一段起點為上一段 occupiedEndsAt；不改既有資料庫排他限制。
- 每個服務段保留獨立 appointment、cardId、加做快照及技師；共用既有 groupId。預約在同一 Store lock／transaction／command 中寫入，全部成功才成立。方案預約時保留額度，完成時沿用原有先買先扣與出席規則；取消釋放該段預留。
- 班表以同筆預約及第 X/Y 段標示；後台明細列行程。顧客端同筆顯示各段，改期／取消按鈕明示僅處理本段。此版不提供整組改期、同時進行或自訂段間空檔。
- 後台服務／加做收款重用現有混合付款編輯器，限 Beauty 支援的現金、轉帳、信用卡、其他。拆分合計等於本次實收，各方式按服務順序分配，單一 command 與 transaction 建立所有付款、現金帳及修訂；重送保留同一識別。退款沿用不可變的原付款紀錄。
- 沿用現有最大 12 段交易與收款界限；每人最多加選 5 個主服務。一般單服務、同行者與其他模組原規則保留。

## 影響範圍

會員預約（BeautyMemberBookingForm）、美業後台原生班表新增預約（ServiceReservationForm 的 itemEntitlements 模式）、班表投影、後台名單與顧客預約紀錄、服務與加做收款。共用付款編輯器新增可用方式限制且保留原本模組的五方式預設。

本次不更改正式通知開關、資料庫 schema、服務／方案售價、方案資格或其他產業模組。同步美業後台操作指南；不新增前台操作指南。

## 驗證與限制

測試包含：依序分段、預設同技師與分別技師、技師資格、後段占用與關店、同行者仍同時開始、不同方案與身分限制、後段方案到期於建立前擋下、持久化起訖與各卡預留、混合金額驗證與 command 重送、後台表單提交雙段安排。

PGlite 載入既有候選 SQL，在隔離記憶體資料庫驗證同顧客相鄰服務段可成立、重疊被排他限制擋下與交易回滾。這不等同遠端正式 PostgreSQL、登入或完整 Prisma 整合驗收。

瀏覽器腳本：`node scripts/qa/beauty-journey-browser.mjs`。實際 React 元件、合成會員／服務／方案，所有請求攔截且 server actions 以明確測試替身代替。檢查 360、390、1366、1920、1024、768 寬度，顧客／後台／混合收款三入口的操作、應付金額、提交 payload 及整頁溢出。截圖與結果存於 artifacts/beauty-service-journey-20261103。
