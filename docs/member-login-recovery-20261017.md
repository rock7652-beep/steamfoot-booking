# 蒸足會員登入恢復：實作與驗收

## 問題與結果

公開體驗可先建立 Customer，再設定官方 LINE 通知；這兩步都不等於完成會員登入。既有手機候選在 onboarding 提前返回確認警示，通知電話綁定卻回覆可繼續註冊，使顧客反覆操作仍無法登入。

本次接通蒸足入口的「本次 LINE token 驗證 → 會員候選 → 待門市確認 → 本人及確認碼核對 → 有期限的精確授權 → 再次驗證 token → 更新登入連結 → 建立 session」。課程門市保留原業務分流；跨 owner、合併、多筆手機及不一致資料仍拒絕，不因電話相符轉移會員。

## 實作邊界

- 沒有既有顧客的新會員沿用原註冊流程。唯一且無 owner 的預建顧客，可在姓名／手機及已驗證 LINE 身分符合既有規則時啟用；相同通知身分不再被當成其他人。
- 其餘可核對候選寫入既有 StoreMemberConnection 確認佇列。`channelKey=login:<channelId>`、`lineUserId=login:<store/provider/subject SHA-256>` 分隔通知請求；不保存 token 或原始 Login subject，不新增資料表。
- 顧客與店長看到同一組確認碼。申請只有 PENDING，沒有建立 session、Account 或會員連結。重送有效申請沿用原碼及到期時間；過期後產生新碼，不能使用舊後台畫面確認。
- 店長在既有「本店會員與 LINE」核對本人、手機及確認碼。server action 檢查 customer.update，交易內再檢查門市權限、模組、通道、手機唯一性、owner、舊登入快照及進行中的授權。
- 無 owner 的體驗客僅在門市確認後建立會員 owner；與其他手機帳號衝突時整筆交易拒絕。既有會員沿用原 owner。
- 核對成功建立 24 小時、綁定精確本次已驗證身分的一次性 LineRebindRequest。新會員採 pinned first capture，舊會員採 pinned Login recovery；通知收件身分不變。授權逾期須重新提交、重新核對，不自動延長舊授權。
- 顧客再次送出資料時，既有恢復服務核對新 token、原 owner／手機／舊身分與候選衝突，再原子更新登入連結並消耗授權；scoped recovery 保留其他門市可能仍使用的全域 credential。
- 已有中央帳號但缺本店關係的蒸足顧客可進入確認表單，這不授予 session 或會員關係。其他 owner 的帳號仍拒絕建立確認申請；課程入口不套用蒸足規則。
- OA 通知確認不得審核登入請求，也不得拒絕登入佇列中的待確認資料；登入核對不寫入通知欄位。
- 取件通知的選取、快照與發送前再核對，以及兩個既有通知連結入口，一律排除 `login:` 核對列，避免把恢復授權當成通知收件資料。

## 呈現與後台操作

- 通知電話綁定回覆明示「僅限 LINE 通知收件」，不再以重新註冊作為登入修復方式。
- 後台分列會員資料、登入恢復狀態、通知。已有會員資料不表示本次登入成功；已授權表示等待顧客操作；CONSUMED 表示連結已恢復，仍需顧客確認實際登入。
- 有效期內未操作、已過期、未核對及已消耗分別呈現。顧客請求確認時顯示黃色待處理區與確認碼；不冒稱已登入。
- 沿用 panel reader、提交防重及顧客切換後的舊回應隔離。確認後失效快取，保留原顧客上下文。
- 後台操作指南 F04 補上門市核對與過期處理；沒有新增會員前台操作指南。

## 驗證

- 18 組相關 Vitest 共 293 項通過：包含新申請及審核、原登入／首次啟用、精確候選授權、不同 owner／門市／通道／過期／舊確認碼拒絕、通知隔離、狀態呈現、課程分流、預覽隔離與後台操作指南。
- TypeScript noEmit 與變更檔 ESLint；未執行正式 migration 或直接更新正式登入綁定。
- Chromium 使用實際 React 元件搭配 fixture services 驗證表單送出、顧客確認碼、店長核對動作的 request/customer/code 參數、授權後狀態與通知不變；確認頁主要操作維持至少 44px。
- 尺寸：手機 320×740、360×800、390×844；桌機 1366×768、1440×900；iPad 1024×768、768×1024、820×1180；320px 窄面板。檢查整頁水平溢出與 JS error。
- 圖片與測試 JSON 位於工作區 /workspace/login-recovery-validation，僅含合成資料。

## 發布與限制

分支 `fix/member-login-recovery-20261017` 只允許既有隔離 Preview DB；沿用 migration-free preview gate。正式合併需要使用者明確授權。

上述測試使用 mocks／fixture，不是實際 LINE、Safari、手機鍵盤或登入後預約／方案的完整業務驗收。正式顧客的單筆恢復申請與此程式發布是不同事項；不得把授權建立或測試通過說成該顧客已成功登入。Preview 部署與真實 LINE 驗收結果另列於 PR。
