# 竹北店一頁式體驗頁 MVP 規格

## 目標

建立一個可由 Meta 廣告導入、適合手機瀏覽的一頁式體驗頁，讓首次接觸暖暖蒸足的顧客感覺自然、安心、有人照顧，並將廣告來源一路保留到 SteamFoot 的預約、報到、收款與正式方案成交。

第一版只做竹北店，確認流程與數據正確後，再套用共用版型到新竹與台中店。

## 已確認內容

- 店別：暖暖蒸足竹北店
- 體驗名稱：蒸足
- 新客體驗價格：NT$499
- 體驗時間：約 45 分鐘
- 地址：新竹縣竹北市科大一路 80 號
- 停車：周邊路邊停車格
- LINE：https://lin.ee/Nki2OjA
- 核心需求：手腳冰冷、疲勞放鬆、睡眠放鬆
- 頁面主要出口：直接預約
- 次要出口：LINE 先詢問

## 顧客流程

```text
Meta 廣告
  ↓
竹北店一頁式體驗頁
  ↓
系統背景保存廣告來源
  ├─ 直接預約：選日期／時段／姓名／手機
  │      ↓
  │   SteamFoot 建立正式預約
  │      ↓
  │   店長報到 → 已到店
  │      ↓
  │   確認收款／建立正式方案 → 已成交
  │
  └─ LINE 詢問：自然開啟竹北店官方 LINE
```

第一版接受並正規化：

- `source`

## 預約串接規則

### 正式預約成立條件

只有 SteamFoot 成功建立有效預約紀錄才算「完成預約」。

不包含：

- 開啟頁面
- 點擊查看時段
- 表單開始填寫
- 送出失敗
- 只有 LINE 詢問

### 必須沿用現有規則

- 分店資料隔離
- 公休與進修日不可預約
- 額滿時段不可預約
- 避免同一顧客重複送出
- 建立時再次檢查名額，避免競態超賣
- 手機已有顧客時，依現有安全規則辨識或提示
- 建立失敗不可記為成功

## 廣告來源保存

預約成功時，來源資料需以不可被一般改期流程覆蓋的方式保存：

- storeId
- source
- campaign
- creative
- medium（選填）
- adset（選填）
- firstTouchAt
- landingSessionId 或 attributionId

來源應掛在潛在顧客／預約歸因資料上，不應只存在 cookie 或瀏覽器記憶體。

### 第一版歸因原則

採 First Touch：首次有效進入並完成預約的來源，作為該筆預約的主要歸因來源。

後續改期、店長協助修改時段、報到、收款，不得改寫原始來源。

## 到店與成交判斷

- 已到店：現有 SteamFoot 報到成功紀錄
- 體驗付款：體驗費收款已確認
- 正式方案成交：正式方案收款已確認，且方案建立成功
- 提前付款不得被視為已到店
- 體驗付款與正式方案成交需分開統計

## 第一版報表最低需求

可依期間與影片素材查看：

- 進入頁面數
- 完成預約數
- 已到店數
- 體驗付款數與金額
- 正式方案成交數與金額

廣告花費第一版可先人工輸入；有花費時再計算：

- 每位預約成本
- 每位到店成本
- 每位正式成交成本
- 正式方案營收／廣告花費

## 事件命名建議

- `experience_page_viewed`
- `experience_booking_started`
- `experience_booking_created`
- `experience_line_clicked`
- `appointment_checked_in`
- `trial_payment_confirmed`
- `plan_payment_confirmed`

所有事件需有唯一 ID，避免重複計算。

## 驗收案例

1. 影片 C 網址進入，完成預約後，預約顯示來源 `meta / campaign / video-c`。
2. 同一頁直接開啟、沒有參數時，來源顯示 `direct`，不可誤歸因廣告。
3. 點 LINE 但未預約，不可列入完成預約。
4. 預約後取消：預約數保留，取消數增加，到店與成交不增加。
5. 預約後改期：原始來源不變。
6. 店長報到後：該素材到店數增加一次。
7. 提前收款但未報到：付款有紀錄，到店數仍為零。
8. 正式方案確認收款：該素材正式成交與營收增加一次。
9. 重複 webhook／重複送出：不得重複計數。
10. 竹北來源不得出現在台中或新竹店資料中。

## 實作切分

### PR-1：手機頁面與來源保存

- 共用體驗頁版型
- 竹北店內容
- 來源參數解析與正規化
- landing session／attribution 資料保存

### PR-2：現有時段與正式預約串接

- 可預約日期與時段
- 正式預約建立
- 名額、公休、重複送出、分店隔離測試

- 報到歸因
- 體驗付款與方案成交分離

- 歸因追溯明細

- AI 自動調整 Meta 預算
