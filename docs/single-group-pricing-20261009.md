# 多人單次金額修正（2026-10-09）

## 問題與修正

蒸足 SINGLE 預約在 expectedAmount 未保存時，詳情與收款直接取 servicePlan.price 或 799，沒有乘 people。收款後端也使用相同錯誤原價，可能限制操作人輸入正確合計。

新增共用 resolveSingleBookingTotal：已有 expectedAmount 時視為整筆總額（包含 0 元），不再乘算；缺值才以方案單價或 799 乘預約人數。詳情金額、預計收款與交易原價皆使用同一計算。多人收款視窗標示「原價（N 人合計）」。

未自動改寫歷史已收交易，也不擅自重算已有金額快照。舊快照若錯存單價，需逐筆確認是否優惠再更正。

## 四模組盤查

- 蒸足：1～4 人預約；本次修正 SINGLE 無快照的回退計算。方案轉單次既有 expectedAmount 為合計，保留。
- SPA：每位同行分別建立 SpaBooking，每筆 totalPriceSnapshot 為其服務項目合計，不能再乘同行數。既有同行入口上限為 3 人，本次沒有擴充 SPA 容量。
- 運動／音樂：CourseBooking 逐學員建立，體驗價格由 clampTrialTotal(..., 1, settings) 計算，每筆單人收款；保留模組業務規則。
- 首次體驗：已有總額與部分到店收款流程，本次未替換其規則。

## 驗證與限制

- 蒸足單次 1、2、3、4 人預設收款、交易 gross/net/amount、已有優惠合計、4 人預約只到 3 人時人工調整實收並保留原因。
- 相關 186 項測試通過；6 項 course-trial.pg 測試因未提供資料庫連線跳過。
- 部分到店沿用現有實收金額與折抵原因，不新增自動人數結算或改寫出席紀錄。
- 受影響 UI：蒸足預約詳情金額與單次收款原價標籤；沿用原 Modal/RightSheet 外框。
- 尚未進行 1366px 桌機、1024×768／768×1024 iPad 及正式預約瀏覽器驗收，不能視為完整業務驗收。沒有正式站寫入或合併。
