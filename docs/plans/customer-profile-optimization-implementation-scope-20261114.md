### 方案卡的精確定義

- 「可預約」是後端核對後可再安排的額度，已扣除預約保留；空白日期格是尚未扣用，兩者不用相等。
- 正常使用填實際日期；同日兩次使用填兩格。請假／未出席有扣用才填日期與對應標示，不扣用不填。
- 手動註銷仍保持獨立語意，不能混成已上課或直接計為人員費用。
- 「購買日」與方案起算日、首次使用日不同。先核對既有日期來源；沒有可靠購買日期時保留空值呈現，不用起算日、今天或推算值補造。
- 方案金額不等於實收或退款。收款明細保留約定／應收、實收、欠款與退款各自定義，不壓成一個含糊數字。
- 歷史方案在總覽下方收合，保留用完、到期、已註銷的實際狀態及同一份紀錄，不搬成另一套資料。

## 四、程式落點與做法

1. 共用外框及導覽：`src/components/admin/customer-profile-layout.tsx`。沿用 `CustomerProfileHeader`、`CustomerProfileIdentity` 與 `CustomerOverviewBody`，補足固定導覽／次要內容的接口，不複製四套外框。
2. 蒸足接入：`src/app/(dashboard)/dashboard/customers/_components/customer-detail-drawer-content.tsx`。調整 `panelTab`、紀錄入口、健康區與 LINE 區；沿用 `CustomerPanelRecordsList`、`CustomerPanelSummaryView`、既有資料編輯與權限。
3. 運動／音樂／美業接入：`src/app/(dashboard)/dashboard/courses/member-workspace.tsx`。調整 `personTab`、主導覽、`detailReturnTab`、資料編輯入口與 `selectCard`，保留顧客／方案／期別／捲動上下文及離開草稿保護。
4. 方案摘要：`courses/card-browser.tsx`、`courses/card-progress.tsx`、`components/admin/plan-card-header.tsx`、`components/beauty/plan-progress.tsx`。精簡常駐摘要，不移除後端的 remaining／held／available 值，不把本次修改重新變成預約日期格。
5. 方案紀錄與管理：`components/admin/plan-management-controls.tsx`、`courses/plan-usage-history.tsx`、`courses/card-entries.tsx`、蒸足 `customer-panel-sessions.tsx`。先列明事件識別與更正關聯，再減少重複呈現；保留完整原始紀錄入口。
6. 音樂歸位：`courses/music-student-courses.tsx`、`music-tuition-details.tsx`、`music-period-overview.tsx`。單張卡、同商品多次購買、期別必須使用 cardId／purchaseId／period 定位，不能僅以商品名稱或 planId 合併。現有 `orders.filter` 的無卡訂單分支必須保留可達。
7. LINE／同電話：`courses/deferred-customer-support.tsx`、`customers/_components/customer-panel-advanced.tsx`、`customers/[id]/line-binding-section.tsx`、`components/admin/course-phone-view-panel.tsx`、`store-member-connection-panel.tsx`。保留相同權威讀寫與權限，頂部入口定位唯一管理區，不在資料底部再複製一份。
8. 美業 adapter：`components/beauty/native-customer-source.tsx`。沿用原生 source 的 `canReadCards`、`canReadTransactions`、`healthEnabled` 與 `canManageMembers`，不因共用 UI 增加服務或財務權限。

既有顧客預讀、快取失效、直接連結、讀取中的錯誤／重試流程要一併遷移，不能只改預設總覽而漏掉預約名單點入、方案詳情或深連結。

## 五、執行順序與完成門檻

以下是同一個整體優化的實作順序，不能只做第一步就回報整套完成：

1. **先補導覽與方案上下文的共用接口。** 規定每個欄位與操作的主要位置，保留舊連結及返回脈絡。
2. **四模組接入同一主結構，精簡方案摘要。** 同時補齊資料頁及適用健康入口，移除重複數字，保留歷史方案。
3. **將紀錄與音樂期別／款項歸位。** 確保沒有方案的事件、未完成訂單與重要待辦仍可找到。
4. **集中 LINE、資料與備註編輯。** 消除重複入口，保留各自不同的授權及唯讀能力。
5. **一次整合驗收後交付。** 逐項標示四模組已改／未改與證據；未覆蓋的能力明列，不以程式可編譯、外框可開或日期格已完成代替整體驗收。

所有相關修改先集中到可審查版本，再建立必要 Preview；同一程式與設定沿用已驗部署，不為相同內容手動重建。不能把 PR #1565 的日期格 Preview 當成本文件未實作內容的驗收證據。

- 不刪除正式資料、不推算缺失日期、不新增資料庫 migration 或放寬權限。
- 本輪程式與預覽不等於正式合併／上線授權；正式發布須依既有交付及核准流程處理。
