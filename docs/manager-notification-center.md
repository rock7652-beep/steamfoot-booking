# 店長通知中心

提醒管理改為「店長通知／顧客提醒／發送紀錄」，最後使用分頁依店別保存在瀏覽器。每位收件人都有總開關及八項提醒開關；總開關關閉保留偏好但停止發送。舊文字模板及手動測試移至進階工具。

| 開關 | 來源／時機 | 預設 |
| --- | --- | --- |
| 當日新預約 | 顧客新增台灣當日預約 | 沿用既有個人設定，未設定為關 |
| 新體驗預約 | 公開體驗預約成功 | 沿用原通知對象 |
| VIP 續購需求 | 顧客回覆續購／VIP 意願 | 沿用原通知對象與負責顧客範圍 |
| 數位管家新名單 | 留下聯絡資料 | 沿用原通知對象 |
| 要求真人客服 | 要求接手，及超過 30 分鐘尚未接手的最後提醒 | 沿用原通知對象 |
| 待確認付款 | 交易进入待確認入帳 | 沿用原通知對象 |
| 服務未完成 | 開始時間兩小時後尚未完成，15 分鐘檢查一次 | 關閉，需主動啟用 |
| 每日待辦摘要 | 台灣上午 9 點，有待辦才發送 | 沿用原通知對象 |

當日公開體驗預約採「新體驗預約 OR 當日新預約」，同一位收件人只發送一則。資料庫唯一鍵為店別、收件人、事件；LINE 推播以紀錄 UUID 作為 `X-Line-Retry-Key`。重試只在原紀錄建立後 23 小時內，沿用原文字及 retry key；已發送的紀錄不再推播。未完成中的同一事件不併發重送。

## 舊收件人遷移

第一次開啟店長通知或發送通知時，交易鎖定 Store 的遷移旗標。環境變數的舊店長和職員 LINE 帳號轉為可見收件人。原有收件人不覆寫、不重新啟用；職員自動匯入僅開 VIP，並保留原本 owner／assigned-staff 條件。旗標完成後不再從舊路徑匯入，因此解除綁定不會自動加回。新增職員日後需透過通知頁綁定及設定。

## 發送紀錄

新店長紀錄與既有 MessageLog、SessionBalanceNotification 以 UNION ALL 合併後統一篩選及分頁。保留顧客連結、LINE 路由、方案、顧客回覆與舊店長通知結果。所有來源及關聯均限制目前店別。ManagerNotificationLog 啟用 RLS，且不授權 anon/authenticated；僅伺服器 Prisma 存取。
