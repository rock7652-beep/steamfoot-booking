# SPA 預約、療程、人員與儲值金：第一性原理設計

## 目標

店長只需要設定一次門市規則、療程與人員固定班表；日常只處理預約及少數例外。顧客選擇療程後，系統自動算出真正可預約的人員與開始時間，服務完成後才結帳。

成功標準：

- 新人店長可在 30 秒內建立一筆預約。
- 一位人員的專業與固定班表可在 60 秒內完成。
- 正常營運不需要逐格排班。
- 療程調價不改動既有預約與歷史帳務。
- 儲值金不能直接覆寫餘額，每次異動都有帳本。

## 名詞與責任

| 名詞 | 負責 | 不負責 |
|---|---|---|
| 專業項目 | 描述人員具備的能力 | 價格、時間、付款 |
| 療程 | 名稱、售價、服務時間、整理時間、必要專業 | 顧客權益餘額、人員班表 |
| 固定班表 | 人員每週通常可接客的時間 | 顧客預約、付款 |
| 班表例外 | 請假、提早下班、臨時加班、保留時段 | 重複建立固定班表 |
| 堂數權益 | 顧客可使用的次數及期限 | 金額餘額 |
| 儲值金 | 本金、贈送金與逐筆金額帳本 | 療程時間、人員專業 |
| 預約 | 當次療程、人員、時間與價格快照 | 直接修改療程主檔 |

現有 `ServicePlan` 與 `CustomerPlanWallet` 是堂數方案及堂數權益，必須保留相容；它們不能直接改造成儲值金。

## 可預約時段的唯一計算規則

一個開始時間只有同時符合以下條件才可顯示：

1. 完整占用區間位於門市營業時間內。
2. 人員具備療程要求的全部專業。
3. 完整占用區間位於人員固定班表內。
4. 沒有請假、保留或其他班表例外衝突。
5. 沒有與人員既有預約重疊。
6. 房間、床位或必要設備仍有容量。

完整占用時間為「服務時間＋整理時間」。整理時間占用內部資源，但顧客畫面只顯示服務時間。

## 正式資料模型

### 第一階段：療程、人員與班表

- `ProfessionalSkill`：門市專業項目。
- `Treatment`：可預約療程主檔。
- `TreatmentSkill`：療程需要的專業，多對多。
- `StaffSkill`：人員具備的專業，多對多。
- `StaffWeeklyAvailability`：人員每週固定接客區間。
- `StaffAvailabilityException`：特定日期請假、加班或調整。
- `Booking` 療程快照欄位：預約當下的療程名稱、規格、價格、服務及整理時間；不另建可被誤改的主檔關聯資料。

所有資料都必須帶有 `storeId`，且關聯需驗證屬於同一門市，避免跨店資料存取。

### 第四階段：儲值金

- `StoredValueAccount`：顧客於單一門市的儲值帳戶，只保存快取餘額。
- `StoredValueLedgerEntry`：儲值、贈送、消費、退款、沖銷、人工調整的不可覆寫帳本。
- `PaymentAllocation`：一次結帳可由儲值金、現金、刷卡或轉帳共同支付。

本金與贈送金分欄計算；修正採反向帳目，不刪除或覆寫舊紀錄。

## 頁面流程

### 療程管理

列表直接顯示療程名稱、規格、售價、服務時間、整理時間、必要專業與前台狀態。新增或編輯使用右側面板，60／90／120 分鐘可作為同一療程的不同規格。

### 人員管理

人員卡片直接提供兩個主要動作：

- 設定專業：勾選既有專業項目。
- 設定固定班表：一次選工作日、開始與結束時間，可快速套用週間。

請假與臨時加班是例外，不進入逐半小時排班介面。

### 預約管理

唯一日常工作台為「時間 × 人員」：

- 點空白：日期、時間及人員自動帶入，只選顧客與療程。
- 點預約：查看、改期、換人、取消、報到與結帳。
- 更換療程：立即重新檢查專業、連續空檔、打烊時間及資源容量。
- 點人員：處理當日請假、加班或保留。

### 顧客預約

固定順序為：選療程 → 不指定或指定人員 → 選日期 → 選可用時間 → 確認。預設不指定人員，以增加成功率。

### 結帳與儲值金

預約只記錄預計內容；服務完成後確認實際療程與加購，再扣儲值金或使用其他付款方式。儲值行為是金流，完成服務才形成服務業績。

## 五階段交付順序

1. 建立療程、專業、人員固定班表、例外與預約快照。
2. 以營業時間、專業、班表、預約及容量自動產生可預約時間。
3. 建立店長每日預約工作台與完整異動紀錄。
4. 建立儲值金帳本、結帳與混合付款。
5. 增加取消費、保留金、候補、智慧分配、破碎空檔優化及業績抽成。

## 安全遷移原則

- 第一階段只新增資料表與 nullable 關聯，不刪除或改名既有欄位。
- 現有預約、堂數方案、堂數錢包及交易流程維持原狀。
- SPA Demo 先使用新模型；正式門市需另做唯讀盤查及明確映射後才遷移。
- 不從名稱猜測療程或專業，不自動改寫正式資料。
- 新舊預約讀取需支援雙軌：有快照讀快照，否則沿用既有欄位。
- 正式 migration 前必須完成同店關聯、權限、資料隔離及回滾驗證。
