# 門市代理店長通知：實作進度

## 目標

小鈴鐺是門市的數位店長：所有店長營運通知都應出現在該門市的小鈴鐺，讓值班人員接手。小鈴鐺的紀錄不能依賴 LINE 收件人、發送開關、發送結果，或個別店長的角色與權限；即使店長調整自己的權限，門市仍須收到通知。通知屬於門市，而不是店長個人。各店獨立設定；保留門市資料隔離與登入人員的讀取、處理權限，不能因通知持續產生而給予無權限人員查看或操作資料的能力。LINE 系統目前的暫停規則維持不變。

## 已完成的局部修正

- 課程模組由學員建立的當日預約，寫入小鈴鐺時列為待處理；按台灣時間判斷當日。其他日期預約仍維持原本的資訊紀錄行為。
- 美業模組由顧客建立的當日預約與公開體驗預約，寫入小鈴鐺時列為待處理，不依賴店長 LINE 設定；門市人員自行建立的預約仍沿用原紀錄行為。
- 已建立通用門市通知的資料表候選及交易內寫入函式，僅儲存事件與目標的參照，不複製顧客或付款明細。課程顧客提交待核帳方案時已接入交易內寫入，核帳時更新同門市通知；課程小鈴鐺已整合付款事件及權限檢查。隔離測試資料庫已安裝候選表並檢查 RLS 與公開角色無讀取權限；PGlite 測試重試去重、門市區隔及失敗回滾。Chromium 合成畫面驗證桌機、iPad 與手機尺寸，測試動作採用 stub，並非登入後業務驗收。**其他付款來源尚未接入，也尚未建立可登入的隔離 Preview；正式資料庫未安裝。部署前必須先完成角色授權及正式 migration，否則方案購買與核帳將因缺少資料表而失敗。**
- 美業顧客提交待核帳方案時已接入交易內寫入，核帳或作廢時處理同門市通知；小鈴鐺及交易查閱權限已接入。新增受限美業資料庫角色的權限候選，已用 PGlite 驗證只能存取美業付款通知且不能刪除；候選角色權限尚未安裝至任何遠端資料庫，部署前須完成。
- 單元測試涵蓋台灣跨日及非當日情況。此修正尚未完成桌機／iPad Preview 驗收，也未合併部署。

## 尚待實作及驗證

- 逐一接入當日新預約、新體驗預約、VIP 續購需求、新名單、真人客服及最後提醒、待確認付款、未完成服務或出席、每日待辦摘要；依各模組實際支援項目處理。
- 新增可跨事件類型使用、按門市與事件去重的通知儲存與讀取；針對相關內容核對員工權限、門市隔離與處理入口，不把通知中的網址直接視為授權。
- 檢查事件產生點：課程的 LINE 功能資格、美業 LINE 總開關與排程等現有前置條件會阻止通知程式執行；需在正確業務事件或排程處獨立產生小鈴鐺，不能僅在 LINE 傳送函式複製訊息。
- 保留原有小鈴鐺開關、待處理／已處理與權限；明確處理既有通知和新增通知的去重、分頁、更新與多人同時處理。
- 驗證停用或無法送出 LINE 時仍有小鈴鐺；同事件多個 LINE 收件人只產生一筆、跨店隔離、無權限無法操作、排程重試與當日臨時預約。
- 驗證調整或移除店長的個人權限、移除店長 LINE 收件人、換班或店長不在店時，門市通知仍持續產生；值班人員可依自身權限查看及處理。
- 在隔離 Preview 完成桌機、iPad 及窄畫面驗證，記錄無法進行的真實 LINE 驗收，交使用者審閱後再決定上線。
