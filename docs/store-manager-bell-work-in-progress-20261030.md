# 門市數位店長通知：實作與驗收狀態

門市小鈴鐺記錄屬於門市的營運事件，與店長個人的角色、LINE 收件人、LINE 開關及傳送結果分離。查閱、開啟對應資料及處理通知仍按登入人員的權限與目前門市判斷。LINE 全域停發維持不變。

依使用者要求，小鈴鐺持續接收營運通知；舊「後台異動通知」設定不再阻斷接收，舊版客戶端的開關寫入會被拒絕並提示更新。裝置上的提示音仍可自行調整；店家 LINE 發送設定維持原狀。

## 已接入的程式

- 蒸足、課程、美業：當日顧客預約；蒸足與美業的公開體驗預約；三模組的方案待核帳、未完成服務或出席、每日待辦摘要。
- 蒸足與課程：數位管家新名單、真人客服請求及未接手提醒；蒸足另有 VIP 續購需求。各模組依現有業務支援項目接入。
- 新通知按門市及事件去重，付款、預約或顧客資料不複製到通用通知表；需要查看時，後端依通知與門市查詢目標。核帳、作廢、完成、改期及客服接手等狀態變動會結束相應提醒。
- 美業排程另行執行，LINE 功能停用時仍能產生門市提醒；首次建立啟用時間，避免補記過往事件。
- 付款通知採用已定案的單行顯示及放大的圓圈，展開後可查看待核帳。

## 驗證與限制

- 2026-10-30 本機 PostgreSQL 17 與隔離網站：美業排程入口未帶正確身分時回 401；授權呼叫會建立服務未完成通知，重跑去重，LINE 發送數為零。店長登入後的小鈴鐺實際顯示「服務未完成」。模擬台灣時間 09:05 的美業每日待辦以本機專用驗收入口驗證建立及去重；蒸足、運動、音樂及另一課程測試門市另經本機實際每日待辦入口手動觸發並確認同店去重。這些不代表正式排程已觸發。
- 美業排程改為先執行數位店長並隔離各工作錯誤：LINE 工作拋錯不阻斷小鈴鐺，數位店長工作拋錯也不阻斷其他工作，例外仍回傳 500。未完成服務查詢改為每次取最多 100 筆尚未通知的事件，避免持續被前 100 筆既有通知卡住；102 筆合成預約透過本機排程確認一人一筆、同店歸屬與無重複，PGlite 另驗 100 加 1 分批。美業試營運與正式營運店均納入掃描。
- 蒸足／課程未完成提醒與真人客服未接手提醒新增尚未記錄事件的獨立掃描，補漏項目只建立小鈴鐺，不擴大原有 LINE 發送及重試掃描；每次分別最多補入 300／300／200 筆，超過時由後續排程批次處理。以 PostgreSQL 17 與本機實際排程確認蒸足與課程第 301 筆、客服第 201 筆各屬正確測試門市，最終版另確認蒸足／課程第 302 筆及客服第 202 筆；重跑不重複且 LINE 發送為零；這不等同正式排程或真實 LINE 驗收。此前手動的店員代建當日預約出現提示屬舊規則，現已調整為不產生預約提示；新版運動 OPEN 方案另已在本機實際驗證顧客預約與通知。
- 隔離 PGlite 測試涵蓋交易回滾、事件去重、跨店、權限、角色受限及 LINE 停用。桌機、iPad、手機尺寸已使用合成資料進行 Chromium 畫面測試；合成畫面不代表登入後完整業務驗收。
- 隔離 Supabase Preview 資料庫已安裝候選表及觸發器，確認一般 API 角色無直接讀取權限。候選變更尚未安裝到正式資料庫；美業正式受限角色所需授權也尚未安裝。
- 正在原 Vercel 專案建立受保護的隔離 Preview；登入後的多模組業務流程、權限與 RWD 驗收尚未完成。真正 LINE 流程亦未在獨立測試官方帳號驗證。
- 此分支不得直接部署正式站。上線前須建立並審查正式 migration、確認資料庫角色及前置順序；缺少表或授權時，方案購買、核帳及預約狀態更新可能失敗。待完整驗收及使用者授權後，才處理正式上線。
- 正式資料庫候選檔順序、校驗值與未驗事項見 [資料庫審查清單](digital-manager-database-release-review-20261030.md)。
