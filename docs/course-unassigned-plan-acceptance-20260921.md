# 未指派方案站內提醒 — 第一階段

- 原 A 店隔離預覽；驗收前不合併正式站。
- 新增首頁「顧客方案待辦」人數，以及設定 → 通知與顧客經營 → 未指派方案提醒入口。
- 名單每頁 30 人，可查看顧客與方案；此階段不發送 LINE，不建立新的收款或方案指派流程。
- 不依賴 CUSTOMER_CARE 加購，但需要 customer.read + wallet.read；沿用店別與直屬店長可見範圍。

## 判斷

列出未合併、帳號可用且沒有本店課程方案成員紀錄、沒有待核帳或已核帳／退款訂單、沒有持卡預約紀錄的顧客。

共用方案以實際成員判斷，不只看購買人。到期、用完、結清仍保留歷史方案紀錄，不列入；純教練帳號亦排除。只有已取消／拒絕且未發卡的訂單不阻擋列入。體驗預約不是正式方案。

從共用方案移除、又從未購買或持卡預約的人，若資料庫已沒有任何成員紀錄，會重新列入；本版不新建成員歷史表。

## 檢查

- 首頁只讀 count；名單單次 SQL 同快照取得總數與分頁，並修正超出頁碼。
- 共用／到期／用完／結清／待核帳／已核帳／退款／撤銷已發卡／已移除但曾持卡預約／停用／純教練／合併／跨店排除。
- 缺少顧客或方案讀取權限不能直接開名單；查詢失敗不顯示假零人。
- 只讀 PostgreSQL 樣本：執行 `node scripts/course-unassigned-readonly-check.mjs` 產生 5 組 SQL；僅使用 CTE 資料，不新增／刪除真實資料。預期全店 40 人、名下 39 人、首頁 30 筆、末頁 10 筆、空店 0 人。
- 指派／共卡／核帳相關操作失效快取；名單重新整理後移出已處理顧客。

LINE 每日彙整、可自訂延遲天數及手機實機驗收不包含在此階段的完成聲明。
