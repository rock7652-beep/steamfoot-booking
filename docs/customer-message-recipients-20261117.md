# 顧客訊息：接收對象與操作列

接續 PR #1583／main 2d829121。使用者提供四模組畫面，要求一起改善操作列視覺及「傳給誰」。沿用此功能的既有發布授權；不新增 migration、cron 或正式外發測試，維持所有停發及 Preview 隔離保護。

## 行為

- 蒸足的次要按鈕與發送／新增操作統一 44px 高度，訊息入口緊鄰新增；窄版可換行。PageHeader 僅增加可選 actionsClassName，其他頁面預設呈現不變。
- 運動／音樂及美業共用工作區只保留一個自動推右的間距，移除新增按鈕的第二個自動間距。學員頁補上學員管理標題，保留原有購課／續購及各模組權限。
- 寫內容與選發送時間直接呈現「傳給誰」、人數及前三位姓名／電話，超過三位可展開完整名單；修改對象返回選人且保留文字與時間。這是已選名單，可發送資格仍由預覽核對。
- 預覽直接呈現前三位可發送姓名，超過三位可展開；排除名單及原因沿用既有呈現。
- 發送紀錄以既有 nameSnapshot 顯示原接收名單，每位列出處理狀態及原因。沿用授權後的本店歷史查詢，JOIN 同時核對 batch 與 store，不查現行顧客名稱，不輸出 LINE userId、token 或 retryKey。上限仍為最近 30 批、每批最多 500 位，無 client 額外讀取或新快取。

## 驗證

- 完整 TypeScript、受影響檔案 ESLint 通過。
- TZ=UTC 的六個顧客訊息測試檔共 38 項通過；本機 PGlite 需 UTC 與正式 PostgreSQL timestamp 解讀一致。新增實際 PostgreSQL 測試覆蓋歷史姓名快照、逐人狀態、資料最小化與跨店隔離。
- 兩套隔離瀏覽器回歸均通過 1366×900、1024×768、768×1024、390×844。涵蓋寫內容／選時間名單、直接顯示預覽姓名、歷史逐人結果、多於三人展開、返回保留草稿、排程、同批確認重試、取消、帶入與單人捷徑。無正式資料或實際 LINE 請求。
- 合成截圖：/tmp/steamfoot-customer-messages-simple-qa/*-timing-recipients.png、*-history-recipients.png。這些是模擬資料元件驗收，尚不能代表正式四模組已登入驗收；hosted Preview、CI 與正式版本證據續記 PR。
