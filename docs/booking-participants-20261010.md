# 多人預約逐人資料、結帳與分析

## 已確認產品規則

- 適用蒸足、SPA、運動、音樂；沿用各模組出席、扣堂、退款、權限與容量規則。
- 一組預約一張卡，清單兩行；原頁彈窗內完成，不跳頁。
- 原預約幾人即保留幾個穩定參與者位置（蒸足最多四人）；補姓名不增加容量。
- 到店用姓名、電話確認既有會員或新增；無個資仍可記錄人次，但方案需對應會員。
- 每人可分別使用個人方案、共卡、首次體驗或單次服務，不能以預約者類型套整組。
- 體驗每人獨立收款並完成，不另外按完成；課程出席規則保留。
- 方案另行收款與開卡，不覆蓋體驗款；一人代付仍記每人款項及共同註記。
- 未到、取消、完成各自處理；全員有結果即整組結束，不另按整組完成。
- 現場加人先檢查容量，另記 WALK_IN；原預約位置數不被改寫。換人保留原個人歷史。
- 方案改體驗須釋放該位暫占堂數／點數，不改其他參與者。
- 顧客營收歸屬、既有會員所屬人員不可因同行覆蓋。
- 不重發整組提醒；體驗關懷依本人實際完成，未到者不入體驗關懷。
- 禁止重複收款／開卡；資料更正、退款、作廢保留稽核，失敗不得顯示成功。

## 分析口徑

- 預約組數、原預約人數、現場新增、到店、完成、取消、未到分開。
- 預約到店率只用原預約位置；現場新增另列，避免超過100%。
- 體驗人次按實際完成位置計算；體驗顧客數同店 customerId 去重。
- 轉購為同店、同一顧客的體驗後有效已收正式方案購買；共卡使用、贈送、補課不算購買。
- 原已購卡顧客後續續購不算新體驗轉購；同一顧客多次購買只算一位。
- 跨月轉購回到原體驗月份；收入保留實際收款日期，報表應標明統計截止日。
- 未建檔體驗仍保留人次及身份缺漏數，不假設同行者等於預約者，不隱藏追蹤覆蓋不足。
- 店家各自獨立顧客分析，不跨店去重。A店卡在B店使用僅計B店服務，不計B店體驗或轉購。
- 購卡收入保留售卡店；店間拆帳不是新增顧客購買收入。
- 退款不刪除到店／體驗歷史；淨收入調整，全退或作廢方案不算有效轉購。
- 清單、首頁、日報、月報、來源／業績／期間分析共用一致事實來源，並可逐人下鑽核對。
- 舊整組紀錄不猜身份、不自動拆款，保留 legacy 明確標示；只有確認後才補齊。

## 盤查證據（origin/main 9695e3b）

- Steamfoot Booking 有單一 customerId、people、attendedPeople，沒有逐人身份及狀態。
- collectTrialPayment 的防重複 guard 以 bookingId 為單位；需改為參與者交易防重複。
- clampTrialTotal 對實收輸入執行上下限截斷。預設上限3000／人，兩人11980可變6000。
  尚未讀取事件店家設定／真實交易，不能宣稱已證實特定案件根因。
- conversion-metrics 的體驗母數為人次、成交為customerId集合，且跨月按購買月，須調整。
- analysis-period、customer-flow-metrics、performance-trends、trial-source-metrics 另有算法，不能只改一頁。
- SPA 已有 SpaBookingGroup 與逐人 SpaBooking；需查逐人入口及匿名／歷史 people 語意。
- CourseBooking 已有逐學員 bookingKind、companionIndex；不能新增一份重複參與者來源。
- 音樂／運動分析已有逐人邏輯，但跨月、退款、匿名與共卡歸屬仍須驗證。

## 本輪實作與完成限制

- 體驗收款明確輸入改為檢查後拒絕超額，不再靜默截斷。
- 更正收款先驗證新金額，再作廢原款，無效金額不作廢原款。
- 現有體驗收款彈窗接上相同驗證；課程自訂收款保留原邏輯。
- 新增純逐人統計及同店顧客體驗cohort轉購算法，含未知身份覆蓋提示。
- 純計算、資料庫服務、實際彈窗與主要分析讀取已接上；功能開關仍關閉，不能宣稱已上線。
- 第二階段已新增 Prisma 參與者群組／位置模型、可審查 DDL 草案、明確初始化與既有會員綁定服務。
- 原預約位置與原人數固定；位置可保留取消／未到歷史，最多四位有效參與者，不把歷史列數當容量。
- service 使用同店查詢與資料庫複合FK、交易鎖與revision檢查；重送不重建位置，同一會員不能佔兩個位置。
- service 不自動讀取建檔、不自動拆歷史收款；已有任何整組交易或已結束預約拒絕自動初始化。
- 方案／補課預約初始化暫時拒絕，直到逐位配堂整合完成，不讓新入口繞過舊扣堂規則。
- DDL 草案只在本機 PGlite PostgreSQL 執行測試，尚未套用隔離或正式資料庫；RLS及anon/authenticated撤權已本機測試。
- 第三階段已新增同店完整手機查詢、確認既有顧客、建立顧客並綁定名額的server actions。新增與綁定在同一交易內，佔用／修訂衝突不留下多餘顧客。
- 原預約彈窗已接上可展開的同行者欄位；查到後確認，查不到可直接新增並加入。電話／姓名使用既有操作草稿保留，查詢使用共用panel reader。
- 新入口由伺服器 BOOKING_PARTICIPANTS_ENABLED=true 控制，預設關閉；須完成後續逐人金流、資料庫部署與Preview驗收才開放，不能把這一階段當完整上線。
- 身分寫入採預約→群組→同行位置鎖順序，拒絕已結束預約及已有未歸屬整組交易後補綁；第一人已逐人收款時仍可補第二人的資料。
- 第四階段已新增逐人體驗收款交易及同交易完成、未到／取消、重送防重複。所有體驗款對應實際參與者，不拿方案金額覆寫體驗費。
- 本人方案入口沿用 AssignPlanForm 並傳入該位 customerId；方案表單寫入仍需獨立隔離端到端驗收，不能把模擬介面當實際開卡驗收。
- 新收款使用現有金融交易、現金營業日、營收快照及點數服務；收款／完成任一失敗時整筆回滾。完成通知以本人發送，成功重試不重發。
- DB 草案擋住舊瀏覽器繞過逐人結帳或改整組狀態。任一人已完成／未到／取消後不能整組改期；已結束參與者的日期、到店／完成事實不得以普通更新重寫，修正需另做稽核流程。
- 彈窗每人可收款、未到、取消名額；唯讀時隱藏所有寫入及已展開收款表單。處理中不能重複送出或關閉上層。
- 完成人次先於整組結束可被分析讀取；主要客流、留存、期間、轉購及趨勢先移除舊群組合計，再加逐人完成事實。
- 來源分析已改共用同店本人有效已收方案事實，扣除退款、排除取消方案、既有付費客及重複體驗；來源到店率只用原約位置，不把 WALK_IN 加入原約到店母數。
- 來源統計仍按預約建立日 cohort，主要成交分析按首次體驗日 cohort，兩者不能混寫成同一月份口徑。
- 本機 PGlite 已驗證逐人收款、回滾、個人歸屬、未到／取消、已收款補同行者及保留歷史；JSDOM 已驗證實際逐人元件、本人方案 customerId、權限切換及連點。未連線正式 DB。
- 已推送原支線並建立草稿 PR #1276。遠端 Vite fixture 使用實際元件、模擬 actions，不連資料庫。
- 已操作 1366×900、1024×768、768×1024、390×844 模擬視窗；補身份、逐人收款、超額錯誤、本人方案與未到皆已 UI 驗證，非真機或完整後端验收。
- UI 驗收發現購買方案成功後整組 busy lock 未釋放，已修正並新增回歸測試。
- 已唯讀確認 steamfoot-preview 是獨立測試專案，尚無逐人兩表；Vercel 原支線專屬 env 查詢沒有設定。未解密連線資訊、未寫入資料庫或變更正式站。
- 補上 exact branch/repository、preview provider、逐人 opt-in flag 及兩條隔離連線檢查；建置只查表／RLS／瀏覽器權限／四個觸發器，不自動套用DDL或建立fixtures。

## 尚未開放的完整性項目

- 現場新增／替換名額：不能只新增一列。須統一所有建約、改期、前台可用名額及營業時間降容量入口的逐人容量讀取與共用鎖，再開 WALK_IN 操作。目前仍未開放。
- 混合卡友／體驗／共卡：須接入各位錢包及暫占堂數釋放；目前方案／補課群組初始化拒絕，沒有繞過原扣堂規則。
- 蒸足兩行清單、首頁／日報／月報／HQ、顧客經營最近到店及提醒來源等非主要分析讀取仍需盤查；不能宣稱所有數據入口已完成。
- SPA 沿用 SpaBookingGroup／SpaBooking、運動音樂沿用 CourseBooking；尚未進行四模組完整情境與退款／跨店驗收。
- 匿名完成及已完成後補會員、更正出席／重新收款的稽核流程尚未建立；目前匿名可未到／取消，但收款須先補身分。
- 正式 migration 與隔離資料庫部署尚未執行；DDL 是審查草案，僅 PGlite 測試。正式功能開關不得提前開啟。

## 必要驗收

1. 兩人各收體驗費、各開5990方案：體驗998、方案11980，不覆蓋、不重算收入。
2. 收第一人後第二人仍待收；全員完成／未到／取消後整組結束。
3. 原約二人、一人未到、現場加一人：原約到店率50%，到店二人、體驗二人。
4. 卡友＋體驗客＋共卡客：三個服務人次、一人體驗，體驗位釋放原占點。
5. 同一位跨月、重複體驗／多次買卡、退款／作廢：cohort按本人去重。
6. 店家獨立體驗及跨店用卡：收入／服務／體驗／轉購歸屬符合上列規則。
7. 舊未拆款資料、匿名後補會員、LINE綁定、重複提交及並行操作不產生重複資料。
8. 1366桌機、1024×768／768×1024 iPad、360／390手機及窄panel，原位置與草稿保留。
