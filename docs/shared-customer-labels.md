# 所屬教練與共用顧客標籤

運動教室的顧客歸屬顯示為「所屬教練」，可指定本店啟用中的教練或原店長。沿用 Customer.assignedStaffId，不增加教練管理權限；音樂教室仍隱藏此欄位。

顧客標籤在同一店家的各模組共用。總部功能項目 customer_labels 控制功能資格；店長於設定另行啟用，預設關閉。分類與標籤名稱最多八字，分類編號固定且不重用，顏色依編號套用八色循環；改名與排序不改色。分類可停用，既有標籤保留並可移除。

顧客與預約名單顯示最多兩個標籤與剩餘數量，選單可連續勾選，即時儲存並於失敗時還原。顧客名單標籤條件在資料庫分頁之前套用。只供店內人員使用；未提供批次貼標籤。

## 驗證

TypeScript 無錯誤；變更檔案 ESLint 無錯誤（roster 原有 unused index 警告）。後端權限、歸屬、功能目錄及課程設定測試通過。測試環境資料庫驗證重複新增不重複、跨店外鍵拒絕、停用標籤可移除，所有測試資料已回滾。

遷移 20260930093000_shared_customer_labels 僅透過 Supabase apply_migration 套用到 steamfoot-preview。新表已啟用 RLS 並撤銷 anon/authenticated 權限，僅經後端權限檢查存取。正式環境未遷移。Preview 建置強制兩個 DB 連線均指向隔離測試專案。尚未完成登入後的瀏覽器端完整驗收，發布前須配置該分支 Preview 連線、核對 Prisma migration ledger 並執行驗收。

## 人工驗收

1. 總部開啟顧客標籤功能項目；店長在設定啟用。
2. 新增 01 分類與數個標籤，建立 02 分類；更名與上移後確認色彩不變。
3. 同一顧客在顧客、課程點名、預約名單的標籤一致；勾選後不用另按儲存。
4. 顧客清單依標籤篩選，翻頁仍符合條件。
5. 停用分類/標籤，既有顧客仍保留且可移除；關閉功能不刪資料。
6. 無 customer.update 權限與跨店檢視不可修改；運動所屬教練可指派啟用教練，音樂隱藏欄位。
