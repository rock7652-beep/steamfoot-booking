## 快取界線

- 新增的資料快取只存在目前元件記憶體，不使用 localStorage、不跨登入者共用。
- TTL 到期後不再回傳舊值。快取不是永久資料來源；沒有把容量或扣堂判斷移到客戶端。
- Mutation 後清除資料及在途請求識別；舊請求即使較晚抵達，也不能重新填入已失效的快取。
- 顧客資料刷新或範圍變更會丟棄側欄快取；月份快取依顧客與店家建立。
- 保留明確的 prefetch=false；不全面 full-prefetch 清單中每個連結。先前預約入口曾發生請求風暴，本次不撤回該修正。
- 新的共用連結只對顧客詳情／編輯及顧客 profile 在 hover/focus 時預載完整頁；其他連結維持 Next 預設預載策略。
- 15 秒內仍可能顯示其他裝置更新前的概覽；實際送出預約、扣堂和收款仍依伺服器最新狀態確認。

## 驗證與限制

- TypeScript、修改檔案 ESLint、完整 Vitest。
- 新增快取測試：過期重讀、預載／開啟合併、失敗重試、mutation 競態、清除時在途回應、門市實例隔離與容量上限。
- 沒有修改 schema、後端權限、扣堂／收款規則。
- Preview 應人工驗收：桌機與手機慢速網路導頁、顧客側欄連續切換、月份來回切換、網路失敗重試、儲存後重開與跨店切換。
- 這份盤查涵蓋路由與常用資料讀取流程；不是每個低頻整合、每種裝置與每個網路錯誤的正式站端到端驗證，也未宣稱所有等待都能由快取消除。
