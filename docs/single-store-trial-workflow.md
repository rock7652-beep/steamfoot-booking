# 完整單店試用流程

## 開通

總部完成建店、模組佈建、店長與排程設定後，在店家詳情按「開通 30 天單店試用」，或使用總部訂閱管理的試用入口。開始日必須是台灣今天，最後一天整日可用。總部可自訂 1–90 天；需要延長時由同一試用入口重新開通，舊訂閱保留為已取消紀錄。正式方案不可由此入口改回試用。

新試用統一為 EXPERIENCE + 有日期的 TRIAL 訂閱，同一交易同步 Store 的方案、日期與 currentSubscriptionId。未帶日期的既有體驗資料不自動遷移；既有正式店不受這次開通規則影響。

## 功能與額度

- 所選模組的完整單店功能，使用者仍依店長／員工原有角色權限操作。
- 可啟用人員共 3 位，包含店長及技師／芳療師／服務人員。超過 3 位須先整理，系統不擅自停用人員。
- 顧客資料 100 筆、每月新建預約 100 筆、自動提醒每月 50 次；月份使用台灣時間。
- 不含跨店總部管理，也不含代辦金流申請與串接。外部服務仍須完成自身設定，費用另行確認。

## 前台與 LINE

交付清單沿用 `/s/{slug}/` 網頁登入、`/s/{slug}/register` 註冊及 `/s/{slug}/book` 預約連結。先用網頁帳號實測註冊、預約、後台查看，不需 LINE 作為開通條件。需要 LINE 流程時再為同一家店設定 LIFF，沿用現有身分綁定；不能靠電話相同就繞過密碼／身分驗證。

## 到期

依目前訂閱判斷，到期日的次日零時（台灣時間）起禁止新增預約及受保護的營運寫入，保留查閱資料。排程僅將既有試用標記 EXPIRED，不再建立無限期免費訂閱；即使排程未跑，伺服器日期檢查仍生效。較新的待付款草稿不取代目前訂閱，也不能解除到期限制。

## 轉正式

總部在原店家訂閱管理編輯目前訂閱，選擇購買方案、ACTIVE 狀態、起迄日及付款紀錄。儲存交易同步 Store 與訂閱，清除 isTrial，功能／額度回到購買方案。仍使用原 storeId、帳號、顧客、預約及前台網址；不建立新店、不搬移或刪除營運資料。編輯歷史訂閱不覆蓋目前正式方案。付款仍由總部依實際收款確認，這不是自動金流串接。

## 驗收與上線

自動測試覆蓋開通日期、3 人上限、單店功能範圍、到期日邊界、原訂閱轉正式、歷史訂閱隔離與 SPA 到期／額度阻擋。正式邀請前仍須在獨立測試店驗收網頁註冊→預約→後台查看→到期→轉正式；LINE 於實際設定後另驗證。沒有執行正式資料遷移或建立測試會員。

測試店最終保留 BASIC / ACTIVE / WAIVED、2 位測試顧客及 1 筆測試預約供檢視，沒有實際收款。尚未完成前台會員自行註冊／預約、LIFF 及方案餘額保留的瀏覽器驗收；不能將上述店長預約驗收視為這些流程皆已通過。
