# 美業公告、側欄、LINE 設定、方案管理與標籤補驗

本批補齊使用者追問的未驗證項目；不修改收款、退款或既有交易分配。不恢復 SPA，不執行 migration 或修改環境、密碼、角色。保留音樂與運動既有功能。

## 變更與原因

- 公告：公開讀取原本只允許 ACTIVE，導致 TRIAL 店已發布圖片仍為 404。允許 ACTIVE／TRIAL，保留停用店、未發布、日期範圍及跨店資產限制。
- 側欄：美業導覽補入既有工單／進銷存入口，保留功能資格與角色權限。人員權限編輯器加入已實作的共用權限選項，不自動授予任何人權限。
- LINE：區分店家資料的官方 LINE 網址與 Messaging API 串接狀態。美業設定使用目前授權店家健康檢查，避免 HQ 店家模式進入全店頁而失敗；只呼叫帳號資訊，不送訊息、不修改憑證或重播待發通知。
- 方案：在既有方案詳情加入註銷、期限提前／延後。要求原因與預期額度／期限、原持有人管理權限、門市鎖及既有 command 冪等控制。註銷保留歷史、不自動退款；仍有預約占用時阻擋。期限不得早於建立日或既有未完成預約。未知結果鎖住原內容，以相同請求確認，不產生另一筆操作。
- 標籤：無既有設定時預設啟用，明確關閉仍保留。美業顧客清單使用已授權顧客的伺服端標籤快照，避免首屏等待另一次瀏覽器讀取；其他顧客透過獨立、有授權且不快取的讀取接口，保留既有批次、過期、門市切換與競態保護，不排在無關 Server Action 後面。
- 自行預約設定：移除空提示 children 形成的多餘邊線／留白，保留真正錯誤及待確認提示。

## 正式設定查核與已授權修復

唯讀確認目標美業店為 TRIAL／EXPERIENCE：已有標籤啟用設定、8 個標籤、2 筆關聯及 3 張啟用的公告。工單有明確 HIDDEN 覆寫；進銷存原已包含於體驗方案。

依使用者要求，只將該美業店的 `work_orders` 覆寫由 HIDDEN 改為 ENABLED，保留來源、有效期間與個別角色權限；同一交易新增一筆 `FEATURE_ACCESS_RESTORE`／AUDIT 紀錄。已檢查預期店家及原始狀態，重複執行會拒絕。未新增店家、未更動顧客／交易／方案資料。這項設定修復不等於新版導覽已發布。

## 仍不得宣告完成

- 店家自有 LINE 憑證是否齊全、實際送達；本批沒有讀取秘密、發送訊息或改變發送旗標。
- 公告發布後的正式匿名接口與資產狀態，待新版發布後驗證。
- 實際登入後工單／進銷存、方案操作、標籤延遲秒數及真機結果。
- 單次／體驗「購買方案」入口完整化、營運全角色彙總不是本批修改範圍，不能以本批測試替代。
