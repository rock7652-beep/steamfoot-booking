## 存取可用後的實測案例

所有案例目前皆 **待執行**；本輪沒有把 DB 唯讀核對或過去單元測試記為 hosted 通過。

| 範圍 | 真實操作 | 通過證據 |
| --- | --- | --- |
| 位置／服務／收費排序 | 店長各調整一次、等待成功、整頁重載／重新登入再查；再復原原順序 | 新 revision 與順序可重讀；復原亦儲存；其餘門市不變 |
| 顧客基本資料 | 專用測試顧客改姓名、Email、地址與緊急聯絡資料，儲存關閉重開；還原 | 重開值與權威 DB 相同；會員連結、notes、serviceNote、方案與餘額不被覆蓋 |
| 顧客備註 | 改備註、關閉重開，再立即編輯基本資料；還原 | 備註留存，接續編輯使用新版本；關閉後的舊回應不覆蓋新視窗 |
| 技師 | 修改專用測試技師的服務資格、固定／百分比基準、沿用／個別時段與工作 grants；重開核對再還原 | 單項修改不遺失其他設定；不影響有既有預約的真實測試技師 |
| 後台人員 | 專用測試 Staff 編輯姓名、識別色與可授權項目，關閉重開；還原 | confirmed-save 回傳版本與重開一致，保留原不可編輯／範圍外權限 |
| 低權限後台 | 使用僅有查看權限的獨立測試 Staff；直接呼叫排序、顧客、技師、人員寫入，而非只看隱藏按鈕 | 後端拒絕且無資料／revision／帳本異動；不得用 CUSTOMER 403 代替此例 |
| 前台身分越權 | 顧客及技師登入後嘗試後台管理接點 | 拒絕管理讀寫，前台原有授權仍可使用 |
| 跨店 | 本店帳號讀取／提交另一獨立測試店的實際 ID；檢查資料與版本 | 讀取不洩漏外店個資；寫入拒絕，兩店內容皆不變；不能只測不存在的 ID |
| 版本衝突 | 兩個已登入視窗開同一筆，先後儲存排序／顧客資料 | 第二筆舊版拒絕且保留輸入，不覆蓋第一筆 |
| 錯誤與重試 | 儲存回應中斷後重開確認，不在未知結果下連續送出 | 查明真實儲存結果，再重試或恢復；不假定畫面回復代表 DB 未寫入 |

## 執行邊界與待補資料

- 必須先能正常經過 Vercel 存取保護，再使用應用程式測試帳密登入；不得合成 app session 或把資料庫管理連線當作登入。
- 正式站與 LINE 不操作。預約、扣次、收退款與方案帳本不作這批測試的寫入目標；僅在驗收前後比較未變。
- 既有此測試店只有 OWNER 後台帳號；低權限 Staff 與第二測試店需先核對是否已有適用的隔離 fixture，沒有才建立專用最小測試資料。不得變更現有店長權限或借用其他任務店家。
- 測試資料每次變更先保存原值、儲存後查權威值，最後還原；稽核紀錄保留，不硬刪除帳本／稽核。涉及既有預約的技師時段調整應由原後端規則拒絕，不能直接改 DB 繞過。
- 前輪自動核准審查拒絕「新增可分享的存取權限」。本輪未重試。若沒有既有驗證可用，要為這個確定的 Preview 建立暫時分享驗證連結，需取得使用者針對這項存取權限的明確同意；這是先前自動審查的限制，不是要求另做 CA、角色或部署架構。
