# 同行預約與資料後補

沿用 SportsScheduleFields 的既有服務模式、CourseOptionSelect，以及蒸足 CompanionSlot。美業資料經 source ports 連回同一個 allocateParty／reserveParty 與原有方案帳本；沒有接回 SPA 或另造一套建檔表單。

| 原狀況 | 本次調整 |
| --- | --- |
| 同行者繼承上方技師及位置，需展開後逐人改正 | 共用日期及開始時間；每人常駐姓名、服務、方案、位置、技師。保留第一位點選資源，同行者自動分配其他合資格且空閒的資源 |
| 單靠前端顯示重複位置錯誤 | 預覽回傳實際技師與床位；確認時鎖定該安排，在 Store 鎖內重新核對，資源被占用則整筆拒絕，不暗中換人或床位 |
| 同一顧客可出現在不同服務列 | 搜尋保留但停用已選顧客，標示已選列；後端也按顧客 ID 拒絕重複，同名不同 ID 不受影響 |
| 後台每位都須先選既有顧客 | 第一位選定顧客；親友可保留資料後補，先保留實際技師、床位及方案額度 |
| 全組體驗開關 | 逐人選可用方案、單次或已設定的體驗價；有效適用方案依最近到期排序，共卡合計可用次數，不新增體驗資格制度 |
| 後補只有既有顧客選單 | 原預約的「補顧客資料」沿用蒸足「資料建檔」；新資料與連結同一交易，既有電話須明確選擇使用此人；重送冪等 |
| 查詢與送出共用 React transition 等待 | 時段查詢獨立管理讀取狀態及版本，新的回應不等待舊查詢；送出仍有互斥與交易重送檢查 |

桌機五欄、平板依容器改三欄，較窄容器自動換行；維持原字級及至少 44px 的操作高度。備註收合、合計及確認操作維持底部可見。姓名搜尋未選定時必須選定結果，或清空後使用資料後補，避免悄悄丟棄輸入。

本輪後補只更新原分項的顧客 ID、姓名、電話及修訂號；不重新預約，不動服務／整理時間、技師、位置、卡片、收費快照、拆帳、扣次。沒有數位問卷或變更既有電話唯一性規則。後台指南 BEAUTY02 同步更新，會員前台不新增操作指南。
