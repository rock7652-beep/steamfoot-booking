## 必要資料保護

- 方案保留與實際扣次分開；「未到」依實際 debit 顯示，不用課程曠課扣堂假設。
- 顧客新增帶穩定請求鍵、店家及建立回條；重送不重建。顧客編輯帶目前修訂，略過的身高／備註欄位不清空既有值。
- 方案結帳核對店家、權威售價、到期日、同店顧客、折抵權限及現金抽屜，保留原 issueCard 冪等交易。
- 原人員儲存核心支援原表單的生日／緊急聯絡人及建立狀態／權限，沿用權限上限、角色層級、最後店主與版本守門。
- 預覽每次 GET 重新授權店家及選取身分；技師不再誤用 Main Staff ID。預覽中的保存、狀態、購買、預約及健康寫入停用，既有預覽寫入阻擋仍保留。

## 續補服務規則、營業設定與顧客匯出（本機驗證）

- `MusicSubjectCatalog` 原教學項目編輯器現在直接承接服務資格與預設計酬；保留客戶售價於既有收費方式，不另外產生單次／體驗產品。服務採真實數值修訂，不把版本偽裝成日期。
- 服務增加 nullable `defaultRate`，原技師個別計酬優先；新預約可沿用服務預設並凍結快照。移除預設須先處理沿用中的技師；移除服務資格沿用原有未來預約檢查，同一交易失敗即回滾。原個別費率及預約快照不改寫。
- 原 `CourseStaffWorkspace`／`SportsCoachFeeFields` 讀取實際服務預設，沿用時驗證服務修訂；未設定預設不允許當作零元。服務基本資料儲存回覆與低權限畫面不揭露技師費率。
- 營業設定改用原 `CourseHoursWorkspace`／`CourseWeeklyHoursEditor`；預約開放仍透過原 `BookableUntilForm` 接美業設定。服務營業核心增加原子多星期儲存，同時保留特殊日期、既有名額資料、30 分鐘間隔、Store 鎖、修訂與既有預約衝突檢查。美業畫面不顯示名額或重複的單一時段控制。
- 顧客匯出接回原顧客清單選單與 `/api/export/customers`；運動與美業共用同一 CSV 表格及公式保護。美業讀取真實方案餘額／占用／可用次數及完成服務；各資料依獨立權限與功能開關讀取，禁止跨店檢視模式匯出。
- additive SQL `scripts/sql/beauty-shared-service-rule-candidate.sql` 僅已套用在固定的**本機合成庫**；尚未套用隔離遠端測試庫或正式庫。
