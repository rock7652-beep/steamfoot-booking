# 美業營運收入分類

## 入口與既有規則

「營運 → 收入分類」提供店家／店長分配、顧客所屬店長及技師服務費彙總。沿用既有規則：店家固定費用歸店家，其餘分潤歸原交易的顧客所屬店長。沒有新增店長獨立比例或改寫既有帳務。

「核帳人員」繼續代表操作人，不作為業績歸屬。店家分配也不冒用目前某位店長作歷史收款人。技師費為另外的應付成本，未強行加入收款分配或推定由哪一方負擔。

## 金額來源

- 使用既有 getBeautyRevenueReport 及不可變收款／歸屬／固定費用紀錄，依實際 SALE／REFUND 入帳日涵蓋完整期間；排除作廢，不只加總交易清單目前頁面。
- 店家、所屬店長、未歸屬、待核對四類合計對上淨收款。跨月退款沿用累計退款差額，分次收款沿用每筆原分配；缺歷史費用不以今日收費設定倒推。
- 依原歸屬 ID 分組，同名不同人維持兩組。總額或單組差額均明示，即使兩組差額恰好互抵也會警示。
- 技師費依所選期間「已完成服務的服務日」及保存的 fee 彙總；累計已付使用這批服務的 FEE＋FEE_VOID。每筆服務各算未付及超付，避免某筆超付抵掉另一筆未付。這是服務費應付餘額，與按入帳日的收款分類分開。

## 存取與效能

- 分類查詢要求美業有效店、report.read、transaction.read、BASIC_REPORTS 及交易功能，並核對預期門市。
- 技師費另要求 teacher.compensation.read、teacher.settlement.read 與技師費功能。未授權時不讀取、不傳送技師姓名及金額。
- 不載入顧客姓名、手機、備註；只回傳分類所需的店長／技師資料。
- 使用原共用 RevenueTabs 擴充口、PageShell、DataTable、InstantFilterForm。音樂／運動未注入新頁籤時維持原導覽。
- 打開分類頁才查整段期間，正常交易清單不觸發彙總。分類用途省略無關的首次購買全店掃描。期間最多一年、台灣時區；收款及技師成本各自使用 RepeatableRead 快照；沒有 module global 或瀏覽器個資快取。
