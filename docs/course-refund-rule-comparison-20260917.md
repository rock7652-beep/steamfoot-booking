# 課程退款承接：既有規則與待確認差異

狀態：未使用全額退已獲授權；部分使用金額算法待使用者確認，不自行套用新公式。

來源：`src/lib/refund-plan.ts`、`src/server/actions/transaction.ts` 的 refundTransaction、`dashboard/transactions/_components/TransactionDrawer.tsx`、`src/server/actions/wallet.ts`。這是程式查核，不代表本輪已實測退款。

## 蒸足實際完整流程

- 營運交易列「⋯」→同頁側窗→退款→選「全額退款（未使用方案）」或「退剩餘堂數」。顯示原購買金額、總堂數、已使用、占用、可退堂數、預計退款；退款原因必填。試算失敗禁止確認，送出有 pending 與錯誤。
- 需要 transaction.refund、店別存取；只接受 SUCCESS 的 PACKAGE_PURCHASE，須有 wallet。
- 任一 RESERVED 堂數即拒絕，先處理／取消未完成預約。COMPLETED 與 BACKFILLED 均視為已使用。
- 未使用全額退：已使用必須為零、可用堂數必須大於零；退原交易 amount。
- 部分使用：單價 `round(原交易 amount / wallet.totalSessions)`；退款額 `單價 × AVAILABLE 堂數`。已使用不計退款、VOIDED 不計。這是現存算法的描述，不是課程已核准算法。
- 原交易保留；新增負向 REFUND 交易並反向關聯原交易；可用單堂額度改 VOIDED，wallet 取消／重算，寫入 audit。用條件更新檢查額度狀態，競爭失敗整筆回滾。
- 退款後原交易仍 SUCCESS；不能只看原交易狀態判斷是否已退。既有防重主要依可用額度已作廢，及交易內條件更新。

## 對應表

|議題|蒸足現況|課程承接／需要確認|
|---|---|---|
|未使用無占用|退原交易 amount，收回可用額度|已授權：退核帳實付金額。必須有真實購買來源；免費指派不能當成收款退款。保留原單、退款單、原因與人員|
|已使用部分額度|round(amount/totalSessions) × availableCount|堂數型卡可對應逐堂；點數型卡每課消耗不同點數，只能對照「額度單位」，不能拿出席人次當分母。是否按點數套既有取整方式待確認|
|折扣|建卡時把折扣後 finalAmount 寫入交易 amount；退款 helper 不改用牌價|課程原購買快照 price 應代表實付；日後若加入折扣仍以核帳實付快照，不能按現行方案牌價回算|
|贈送|helper 沒有區分付費／贈送單堂欄位；分母只看 wallet.totalSessions，AVAILABLE 也不帶價格來源|課程 GRANT 也可能來自手動指派，沒有獨立付費／贈點分攤。不可假設贈點可退現金。遇額外加贈／調整須明確辨識來源再試算；待確認是否把贈送算入總配額分母，以及消耗順序|
|占用|任何 RESERVED 先擋退款|課程 reserved>0 或仍有 RESERVED booking 均擋；報到未完成仍算占用；不可退款與預約並行超額|
|曾退款|可用堂數 VOIDED；原交易不改狀態；無可退額度即擋|明確關聯原購買与退款紀錄、在同店交易鎖內核對；重送回同筆結果，不重退、不重收回額度。不能只依 remaining 推算既往已退金額|
|更正出席後|蒸足按單堂歷程處理|課程退款卡不可透過更正重新恢復可用餘額；已退款額度與歷史更正關係需納入交易保護|
|金額取整|每單位先四捨五入再乘剩餘數；helper 無「累计退款不超原實付」獨立上限|有尾差風險（例如 100/6→17，六單位為102）。不將此算式未經確認直接套課程點數；須先確認尾差／上限規則|
|作廢與退款|作廢用於 key錯／重複／未收款；退款另建負向交易|保留兩種操作語意，均要核對占用／使用／歷史，不刪訂單或改蒸足扣堂|

## 已確認執行邊界

先完成未使用且無占用的實付全額退款與所需工作台／資料關聯；部分使用退款保留完整對照與試算需求，等待商業規則確認，不假稱已支援，也不刪掉此需求。其他架構工作持續。
