## 已接入

- Dashboard：以帳號、角色、人員、讀取門市、查看門市、模組、權限建立 keyed boundary；切換範圍重掛子畫面，清除舊選取、請求與本地快取。
- 共用狀態：分頁 sessionStorage，版本化、8 小時期限、格式驗證、無法存取時退回記憶體。只儲存操作中的草稿或呈現條件，不儲存可執行請求。明確登出清除本功能保存的內容。
- 備註：蒸足預約本次備註／店內備註、蒸足顧客明細、SPA 服務偏好、課程顧客店內備註，共用 RetainedNoteEditor。
- 草稿保留：關閉、切换顧客、元件重掛及同帳號重新登入後重新開啟，保留未送出的備註；不自動送出。背景新資料不取代輸入中的文字。
- 儲存：同步 ref 防連點；失敗保留輸入；成功直接呈現內容。可復原剛儲存的備註，復原同樣需要 CAS。
- 多人修改：資料庫 updateMany 同時比對門市、ID 與原始備註；衝突回傳授權範圍內的目前內容。使用者檢視後才可用自己的輸入繼續儲存。不把備註全文記入 audit。
- 網路不明結果：若前次已寫入相同備註，下一次 CAS 核對到相同值即確認，不再次寫入或增加 audit。
- 營運追蹤：各筆備註獨立保存，切換不清空；成功僅清除該筆，取消修改需確認。

- 返回位置：依帳號門市與完整頁面 URL 保存捲動位置，返回時刷新並復原；使用者一操作即停止自動捲動。

## 範圍與限制

- 這不是所有表單的自動草稿：顧客完整基本資料、排課、方案完整編輯、金流與交易仍依原流程。
- 既有舊呼叫 updateCustomerServiceNoteAction／updateBookingNoteAction 未傳原始值時維持相容；本批共用編輯器均傳原始值。整張顧客表單仍須另做版本控制，不可宣稱所有写入入口都具備 CAS。
- 課程既有顧客的備註改由獨立編輯器修改，基本資料表單不再提交舊備註，避免同頁互相覆寫；新增顧客仍可填寫備註。
- 登入逾時後只有重新開啟相同頁面／顧客才恢復草稿；不自動導回原操作、不重送交易。明確登出會清除草稿。
- 草稿限同一瀏覽器分頁，最多保留 8 小時；不是跨裝置同步。瀏覽器禁止儲存時只保留本次掛載的記憶體。
- UI 互動測試使用真實 React 元件與受控 action 回應；資料庫 CAS／權限測試使用 Prisma 邊界 mock，未冒充正式資料庫或登入後實站端到端驗收。
- 不更動現金帳、課表、扣款扣堂、批次交易規則；前一輪預約逐筆鎖與只讀核對維持。
