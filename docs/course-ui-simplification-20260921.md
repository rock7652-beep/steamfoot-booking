# 課程介面減法：授課設定與指派結帳

## 範圍

僅課程模組，沿用原 A 店隔離預覽；不合併正式站，不修改正式資料，不增加 migration。

## 修改

- 人員列表可直接開啟授課設定；有管理權限直接編輯，無權限保持唯讀。
- 可教授課程與每堂固定費同列，無逐課開合；整份表單一次儲存。
- 費用讀取失敗禁止儲存；歷史非固定費不擅自換算，須填入固定費。
- 人員快照與費率 revision 防止舊資料覆蓋；資格／費率在同一 transaction 儲存。
- 仍有未結束課次時，保留先交接再移除資格的阻擋；不更新既有課次快照。
- 從顧客進入指派時直接帶入顧客；1024px 以上雙欄，較窄單欄。
- 優惠為無優惠／折抵金額／打折；九折轉為既有後端的 10% 折抵，不重算舊交易。
- 不預選收款方式；轉帳才顯示後四碼，零元不要求付款方式。
- 底部持續顯示實收與一次確認；內部成本分配摘要依既有交易檢視權限顯示。
- 維持成本下限、後端權限、發卡入帳原子性與 requestKey 防重送。

## 驗證

- 新增 19 項測試：9 項授課 action、4 項授課介面、6 項結帳介面。
- TypeScript 與本次修改檔案 ESLint 通過。
- 完整 Vitest：5,288 項通過、54 項跳過、零失敗；604 個測試檔通過。
- 既有結帳／計酬／人員權限定向 27 項通過。
- 實頁驗收未通過：瀏覽器 refresh tabs 持續逾時，未強制關閉既有草稿。
- 新授課批次 transaction 尚未執行真實 PostgreSQL 故障注入驗收；不可將 mock 測試描述為真實資料庫回滾驗證。
- 實體 iPad 直橫向、手機鍵盤與登入後端到端流程仍待驗收。

## 驗收入口與順序

原 A 店登入路徑 `/hq/login?store=course-start-0918-a`，不是預覽網域根目錄（根目錄為官網）。

1. 人員管理 → 授課設定：不展開課程，勾資格、改費用後一次儲存；重新開啟核對。
2. 在有未結束課次的人員取消資格，確認阻擋且費用未部分儲存。
3. 顧客管理 → 指派方案：顧客帶入，核對九折、轉帳後四碼、零元與低於成本情境。
4. 網路失敗時輸入保留，重送不重複發卡／入帳；確認後回到原顧客方案區。

上述操作只在隔離驗收資料執行；正式發布仍需完成實頁與資料驗收。
