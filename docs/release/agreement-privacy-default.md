# 約定書個資告知自動帶入與操作按鈕排列

2026-11-04 使用者指出店長不知道平台儲存／保存資訊，以及「簽署紀錄」按鈕落在標題列中央。延續三模組約定書，僅修正此兩項操作問題。

## 行為

- 新草稿或原本空白的個資告知，自動組成店家名稱／營業登記名稱、負責人、聯絡方式、用途、資料類別、受託平台／雲端供應商、保存原則、當事人權利及不提供資料的影響。
- 系統產生的完整告知以唯讀預覽呈現，店家補充說明選填。修改店家資料時即時更新；後端保存／發布時重新產生，避免用戶端更改系統告知文字。
- 原本非空白的手填告知保持原樣，可繼續編輯，或明確選擇改用系統告知。清空手填文字時保持編輯，不跳換模式。
- `privacyNoticeMode` 與 `privacySupplement` 為可選 JSON 欄位，沒有 schema default 或歷史資料更新；閱讀既有 immutable 文件仍採當次儲存的條文，不重建或覆寫。
- 簽署紀錄與返回設定使用同一個右側操作群組；窄容器可換行，保留既有左側設定步驟。

## 已核對的文字依據

正式 Supabase 專案 qijlnhtpbintanzpxkvf 管理 API 回報 ap-northeast-1（日本東京），狀態 ACTIVE_HEALTHY。約定書版本及簽名 PNG 由 coursePrisma 使用 DATABASE_URL 保存到同一資料庫；Vercel 提供網站及請求處理。因此文字說明資料主要保存於東京，網站／傳輸處理可能跨境，不宣稱所有處理都僅在東京。

現行沒有自動到期刪除或固定保存年限，因此不填入測試原型的 1825 日或五年，不承諾自動刪除。採服務、契約管理、權益證明、爭議及法定保存必要期間的敘述；權利及刪除申請仍經店家確認身分並依法處理，不以告知文字暗示平台新增自動刪除功能。範圍限簽署資料，額外用途由店家補充及另外履行必要告知／同意。

## 驗收

涵蓋三模組首次空白、自訂／舊文件相容、店家資訊更新、補充文字、偽造平台告知後端重建、保存冪等與發布快照一致。合成 React 設定預覽：1920/1366/1024/768/600/390；操作按鈕相鄰、無整頁溢出，儲存失敗保留補充文字。三模組 PDF 擷取驗證店家、平台與保存說明。不宣稱真機通過。

不新增 migration，不改預約、購課、扣堂、付款、通知或各店啟用狀態。新 Preview 限精確 fix/agreement-privacy-default 分支、隔離測試 DB 及停用通知；正式發布沿用現有功能設定，不使用測試資料。
