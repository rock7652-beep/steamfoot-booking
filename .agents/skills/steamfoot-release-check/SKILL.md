# 發版驗收與文件同步

先讀 [AGENTS.md](../../../AGENTS.md)、本次 PR 與原作者交接、適用的部署／migration 規範及明確授權。保留原工作與證據來源。

## 先確認動作的副作用
- 分別確認本次是否授權本地修改、push／建 PR、Preview、合併、正式部署、migration 與外發。允許其中一項不代表其餘項目獲准。
- push 或建 PR 前唯讀檢查適用的 GitHub workflows、部署整合與分支設定；文件變更也可能觸發部署或安裝腳本。不能證明副作用在授權內時，先交付本地 diff／patch 與確切阻擋，不擅改部署設定來放行。
- 測試環境需確認資料庫、帳號、門市與通知的隔離，不能僅憑網址含 preview 判斷。未確認前不執行可能寫資料或外發的案例；既有停發不得自行恢復。
- Cloudflare 依目前路由、設定及變更影響判定必要性：無關記錄不適用；必要則核對可取得的證據，存取受阻列為該依賴未驗。不得沿用過往跳過宣稱已驗，也不把無關 Cloudflare 檢查當全案發布門檻。

## 版本與測試
- 固定待交付 commit 與 PR head，列出必要的格式、lint、型別、單元／整合及業務回歸檢查；文件／Skill 變更按影響面驗格式、引用與行為，不把程式測試無條件套用到文件。
- 用最終版本執行適用檢查，記錄命令、環境與結果；修改或解衝突後重驗受影響部分。局部通過不代表全量通過。
- UI 依 steamfoot-ui-review 的證據要求；migration 另核對指定版本、checksum、前後資料及獨立授權。既有安全風險不能因本次對帳成功而標為已修復。
- 如已獲發布授權並實際發布，才核對遠端 commit、部署 ID／URL／來源 SHA、狀態與適用 smoke test；未發布則明確保持「未發布」，不能用測試成功替代版本上線證據。

## 交付
列出：版本與環境、變更範圍、通過／失敗／未執行、已知風險、同步的規範／後台指南，以及尚需授權的動作。引用單一維護中的規範，不新增相互矛盾的摘要。
有必要檢查失敗、版本無法對上、授權不足或存取被拒時，不宣稱可發布／完成正式驗收；繼續可安全完成的獨立檢查，不換路繞過限制。
