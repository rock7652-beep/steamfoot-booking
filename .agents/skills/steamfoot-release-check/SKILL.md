# 發版驗收與文件同步

先讀 [AGENTS.md](../../../AGENTS.md)、本次 PR 與原作者交接、適用的部署／migration 規範及明確授權。保留原工作與證據來源。

## 先確認動作的副作用
- 分別確認本次是否授權本地修改、push／建 PR、Preview、合併、正式部署、migration 與外發。允許其中一項不代表其餘項目獲准。
- push 或建 PR 前唯讀檢查適用的 GitHub workflows、部署整合與分支設定；文件變更也可能觸發部署或安裝腳本。不能證明副作用在授權內時，先交付本地 diff／patch 與確切阻擋，不擅改部署設定來放行。
- 測試環境需確認資料庫、帳號、門市與通知的隔離，不能僅憑網址含 preview 判斷。未確認前不執行可能寫資料或外發的案例；既有停發不得自行恢復。
- Cloudflare 依目前路由、設定及變更影響判定必要性：無關記錄不適用；必要則核對可取得的證據，存取受阻列為該依賴未驗。不得沿用過往跳過宣稱已驗，也不把無關 Cloudflare 檢查當全案發布門檻。

## 建置溝通規則
- 先集中相關修改，完成本機可跑且與範圍相符的測試、型別與程式檢查，再建立必要預覽；查明 push／PR 是否自動建置，避免自動完成後又手動重建。減少多餘建置，不省必要測試；純文件依下節驗格式、引用與行為。
- 建置或其他可能增加費用的操作前，說明必要性、可否沿用現有預覽及不能沿用的原因、可能費用與估算限制、是否在既有批准範圍；無法估算就如實標示。同一版本、設定與驗收環境仍適用時重用既有預覽，不為重看畫面部署；核對來源 SHA，不用過期預覽驗新版。
- 已有授權且無其他阻擋，說明後繼續，不為每次告知重新問批准；超出範圍或規則要求才確認。最新內容若無適用預覽，交代完成必要驗收的最小步驟與可能費用，依既有授權繼續，不以節費為由永久停在本機或打包。
- 完成後依下方交付格式分清成果與下一步；受阻須交代精確動作、目標、原因、已完成部分、是否執行／待確認及最小解法，不換路繞過拒絕。不得為節費自行停用正式站、調高預算或更改部署設定。

## 版本與測試
- 固定待交付 commit 與 PR head，列出必要的格式、lint、型別、單元／整合及業務回歸檢查；文件／Skill 變更按影響面驗格式、引用與行為，不把程式測試無條件套用到文件。
- 用最終版本執行適用檢查，記錄命令、環境與結果；修改或解衝突後重驗受影響部分。局部通過不代表全量通過。
- UI 依 [steamfoot-ui-review](../steamfoot-ui-review/SKILL.md) 與 [操作情境](../../../docs/operation-experience-scenarios.md) 的證據要求；migration 另核對指定版本、checksum、前後資料及獨立授權。既有安全風險不能因本次對帳成功而標為已修復。
- 如已獲發布授權並實際發布，才核對遠端 commit、部署 ID／URL／來源 SHA、狀態與適用 smoke test；未發布則明確保持「未發布」，不能用測試成功替代版本上線證據。

## 交付
任務回覆結尾遵循 [AGENTS 的任務回覆原則](../../../AGENTS.md#任務回覆原則)。
分清「檔案完成、已上傳（標明分支／PR）、預覽可驗、正式可用」的實際狀態，不以交付包完成暗示新版已上線。列出：版本與環境、變更範圍、通過／失敗／未執行、已知風險、同步的規範／後台指南，以及尚需授權的動作；依 AGENTS 指明下一步由誰執行。引用單一維護中的規範，不新增相互矛盾的摘要。
有必要檢查失敗、版本無法對上、授權不足或存取被拒時，不宣稱可發布／完成正式驗收；繼續可安全完成的獨立檢查，不換路繞過限制。
