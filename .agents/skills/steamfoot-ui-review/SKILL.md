# 介面簡化與操作驗收

先讀 [AGENTS.md](../../../AGENTS.md) 與唯一正式設計來源 [UI／Settings Framework](../../../docs/STEAMFOOT_UI_Settings_Framework.md)。本 Skill 提供工作流程，不另訂視覺規範或取代最新 Framework。

相關 UI 任務開始前讀 [操作情境 01–10](../../../docs/operation-experience-scenarios.md)，按影響範圍選用並記錄不適用理由；這是驗收參考，不另訂視覺或業務規則。

## 設計／修改
- 根據既有任務與 PR 確認要解決的操作困難、受影響入口、角色與模組；先找可沿用的骨架與元件，若不適用才說明新增理由。保留各模組的資格、方案及交易規則。
- 畫出使用者的最短操作路徑：先看狀態，需修改才展開；保留字級、觸控空間與必要資訊，不用縮字或隱藏關鍵狀態換密度。
- 依 Framework 檢查清單搜尋／篩選、設定層級、錯誤就地呈現與成功回饋。涉及側滑或彈窗載入時，另讀 [panel-loading-inventory](../../../docs/panel-loading-inventory.md)，核對現行入口與讀取機制，不照搬已封存模組或歷史驗收結論。
- 共用元件需盤點其他使用入口；快取摘要不能取代金額、名額、額度及後端權限／交易核對。

## 完整資料與操作感受
- 點開後以完成當前工作所需的完整、正確、可操作資料為目標；外框、摘要、佔位或「核對中」只能算立即回應，不能算資料可用或改善完成。非關鍵資訊可稍後補齊，但不得阻擋主要工作。
- 按本次範圍選測首次冷啟動、再次暖啟動、切月及修改後返回（情境 01、05、07）；從登入／入口一路觀察，不把等待移到前一頁。分別記開始操作、立即回應、完整正確資料可用與任務完成時間。
- 比較前後固定帳號／角色、門市、資料量、裝置／瀏覽器及網路，標明快取與預取狀態；每條路徑記次數、中位數、最小至最大範圍及失敗／異常，不只最好一次。核對預期與實際筆數、必要欄位及結果；只量後端或開窗時間不能代表端到端時間。效能門檻依任務約定，不自行捏造秒數。
- 低風險、可回復且能處理衝突的編輯才評估樂觀更新（情境 03）；未確認不顯示已儲存。失敗保留草稿，較舊失敗不能回滾較新成功或吃掉新輸入；多人同改須明示衝突。
- 付款、扣堂與預約等交易（情境 04）必須確認權威結果才顯示成功；分驗連點、重送、刷新、冪等與相關資料一致性。逾時是結果未知，保留原交易識別查回最終結果，不當成明確失敗或另建可能重複的交易；按鈕鎖定不能代替交易防重。
- 快取、預取、Drawer、並行讀取及局部更新均依現有架構與情境選擇，不要求每頁套用全部技術；適用時仍遵循 Framework 的共用元件與載入規則。

## 驗收
- 依實際入口覆蓋官網／前台手機、後台桌機與 iPad、共用元件窄容器。依 Framework 選擇尺寸，記錄實測值；不要將瀏覽器模擬尺寸寫成實體裝置驗證。
- 驗證儲存／取消、關閉重開、返回、tab／篩選／捲動保留、未儲存內容、重複點擊與中斷重試；面板另驗換人／換店與晚到回應不串資料、不覆蓋草稿。
- 按情境 02、06、09、10 核對搜尋範圍、空／錯誤／更新失敗狀態、門市／角色／登入切換及直接連結；舊 scope 的快取或晚到回應不得閃現或覆蓋新 scope。HQ Hidden／Locked／Enabled 沿用 [專案三態定義](../../../docs/hq-feature-three-state.md)；Enabled 只表示功能已開通，角色與資料權限仍須另驗。
- 使用可確認隔離的測試資料與適當帳號。需要 Preview 時先走發布檢查，確認授權與部署／外發副作用；不得為 UI 驗收提交正式收款、預約或通知，也不得自行恢復停發。

## 完成證據
任務回覆結尾遵循 [AGENTS 的任務回覆原則](../../../AGENTS.md#任務回覆原則)。
交付入口／模組、精確版本與環境、尺寸與裝置類型、操作案例結果、截圖及限制。分清靜態 fixture、登入後流程、模擬尺寸與真機。
登入、隔離資料或必要依賴受阻時保留已驗結果，列明未驗；不標完整業務通過。文件同步遵循 AGENTS 的後台指南範圍，不重建會員或「我的工作」前台教學。
