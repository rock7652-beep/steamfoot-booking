# 任務接手與影響盤點

先讀 [AGENTS.md](../../../AGENTS.md)。本流程只整理與執行已授權任務，不因接手取得合併、部署、正式資料寫入或外發權限。

## 接續現有工作
- 找到原作者／執行任務、PR、分支、精確 commit、已完成與待辦證據；可接續就優先接續。無法聯絡原作者不代表可另做一套，先核對現有成果與使用者安排。
- 核對最新需求、明確授權及被取代的方案。既有文件描述的「目前狀態」、歷史驗收、聊天結論都需對照現在版本；衝突先標出，不把舊 bug、繞路或臨時豁免固定為規範。
- 以目標、範圍、不做事項、成功條件整理任務。只讀問題不要升級為修復；草稿／審查不要升級為發布。

## 確認影響再動手
- 列出受影響入口、門市／模組、角色、共用元件、資料及通知；共用呈現不等於共用方案、扣堂或退款規則。引用適用的現行文件，不複製第二份業務規則。
- 涉及 UI 時依任務範圍採用本 repo 的 steamfoot-ui-review；只讀盤點不因此啟動實作或操作驗收。準備交付或發布時用 steamfoot-release-check，只讀取相關 Skill。
- 若涉及 Cloudflare，先以目前路由／設定／問題證據確認它是否為本次必要依賴；無關則記錄不適用，必要但存取受阻則只暫停依賴部分。不得把歷史跳過當永久豁免，也不要求所有任務一律檢查 Cloudflare。
- 發現停發中的通知，保留其狀態並核對原因與原決策；不得為了測試或「恢復正常」自行啟用。

## 交接與停止
任務回覆結尾遵循 [AGENTS 的任務回覆原則](../../../AGENTS.md#任務回覆原則)。
輸出一份短摘要：原作者／PR／commit、最新決策來源、目前授權、影響面、已證實結果、下一步與阻擋。保留不確定項目，不宣稱已修復。
需求或版本衝突、既有工作重疊時先釐清；遇權限拒絕，回報確切動作與原因，不換路繞過。可繼續無依賴且已授權的部分。
